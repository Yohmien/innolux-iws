# IWS+ 物料储位分配计划与锁定方案

日期：2026-10-26。状态：设计稿，可进入实施拆分；未实现、未执行并发或设备联调。本文细化[在库管理完整方案](inventory-management-design-20261026.md)§9.1；规则生命周期、空间树、载具属性、计划平台及父业务挂载边界沿用主方案，现有库结构证据见主方案附录。

本期验收锁定/安全释放、物料变更挂载和溯源审计的通用底座，用隔离fixture核对合同；文中入库/出库等仅为后续挂载示例，不要求为底座验收完成具体业务接线。冻结/解冻不在本期范围；尊重既有扣留状态和安全释放分配锁不意味着实现解冻业务。

## 1. 业务边界

储位分配是由已注册父业务挂载的计划能力，不是独立业务。本期以入库/出库为首批示例，不创建独立分配业务单；`businessType`、`planType`均从可扩展目录解析，后续业务注册允许挂载关系后可复用，不以INBOUND/OUTBOUND封闭判断。正式调用沿用父业务身份、业务号、明细和权限，由其协调器挂载锁位或释放计划。

父业务可在入库目标、出库来源或确实需要的内部目标位置挂载 `ALLOCATION_LOCK`，在失败、安全取消或需要退回任务资源时挂载 `ALLOCATION_RELEASE`。入出库共用同一套计划、规则执行和锁账合同；没有父入出库业务时只能查询或只读模拟，不能创建正式计划、分配锁或释放事实。

顶层载具和独立物料标签均为不可拆单元，本计划不得自动拆分。生产拆分另建生产业务，换载或拆载另建装载业务。规则配置、设定/发布、更新和退役仍按主方案业务族管理；规则执行是入出库业务下的计划执行明细和领域事实，不产生独立业务头。

## 2. 计划挂载与身份

| 项目 | 固定合同 |
| --- | --- |
| 父业务 | 允许目录已注册且配置了挂载权限与合同的业务，入出库为首批示例；父业务保存挂载范围、期望任务键、结果屏障和关联实例 |
| planType | `ALLOCATION_LOCK` 执行锁位链；`ALLOCATION_RELEASE` 执行释放链；二者均为可复用计划类型 |
| taskKey | `<businessType>:<parentBusinessId>:<lineId>:<allocationUnitId>:<round>:<phase>`，在全局 `businessType` 内唯一；`phase=LOCK/RELEASE`，同明细多个不可拆单元不得共用一个键 |
| 实例数 | 一个 phase 任务只绑定一个对应 planType 实例；同一父业务/明细/round 的锁位与释放各一个 phase 任务，不把一个任务挂两个实例 |
| 映射 | `LOCK→ALLOCATION_LOCK`，`RELEASE→ALLOCATION_RELEASE`；重试沿用同一 taskKey，以实例 attempt 区分，不另造业务身份 |
| 屏障 | 父业务持久记录 expected taskKey 集合及实例结果，全部满足或显式停留后才推进下一步；不能用页面状态代替屏障 |

父业务协调器负责挂载、实例定位、去重和结果屏障，计划执行器只推进一个 planType 实例。锁位任务先完成不等于父业务入库完成；释放任务完成也不等于实物回到原位。父业务仍需等待真实到位、离位或对账证据。

## 3. 锁、占用与状态

```text
可分配 ──ALLOCATION_LOCK/EVALUATE_ALLOCATION+RESERVE_STORAGE+VERIFY_ALLOCATION──> LOCKED
LOCKED ──入库到位证明且库存位置同事务提交──> OCCUPIED
LOCKED ──已验证无外部效果并执行 ALLOCATION_RELEASE──> 可分配
LOCKED(effect=UNKNOWN/ACCEPTED) ──只有对账证明未入位才可释放──> 可分配
LOCKED(effect=UNKNOWN) ──禁止超时自动释放──> 保持 LOCKED
OCCUPIED ──出库实际离位事务扣减──> 剩余占用/锁/规则重新计算可分配
```

分配锁与物理占用是两类独立明细账：`wms_allocation_lock` 记录父业务/明细、taskKey、实例、round、锁类型、储位、容量份额或实体槽位、规则/空间版本和效果键；`wms_storage_occupancy` 记录已经到位的真实占用。锁不是库存，占用不是锁；聚合分别显示已占用、有效锁定、扣留、可分配。

允许多料的储位锁容量份额；短事务按物理储位 ID 顺序加数据库互斥锁，重读安全门禁、占用、锁和扣留后原子写入份额。要求单实体独占时锁实体槽位键。数据库行锁只覆盖选位和写锁事务，实际人工/设备处理期间不持有长事务。

释放只撤销本父业务任务创建的份额，不修改物理占用。若仍有其他占用或锁，储位只恢复相应容量，不显示为空闲。聚合可分配量按维度计算“物理容量－占用－有效锁－业务扣留”；单位不同不得直接相减。所有占用与锁结束且规则允许时，储位才全局可分配。

## 4. 输入白名单与快照

规则只能引用属性目录登记字段及操作符。字段键、类型、来源、单值/集合语义、空值策略、规范化器、单位和精度均由服务端冻结；客户端展示名、任意列名、SQL、脚本或未登记别名一律拒绝。

| 来源 | 允许字段 | 语义与约束 |
| --- | --- | --- |
| 物料生产信息 | `materialNo`、`materialCategory`、HF/RS 等登记属性、`productionDate`、`batchNo`、`supplierId`、`customerId`、尺寸、BOM 层级/用量/版本、最终成品料号/类别、数量、单位 | 按物料单元 ID 冻结；空值只命中显式 `IS_NULL`，不默认通配；日期和数量使用冻结解析/精度版本 |
| 载具汇合属性 | `carrier.aggregate.<attr>.singleValues`、`.setValues`、`.conflict`、`.leafRefs`、载具自身规格属性 | 由有效叶子料汇合，无冲突保留单值，冲突保留去重集合与叶子引用；载具自身规格用独立命名空间，不能覆盖原物料值 |
| 当前物理树 | 根/节点角色、`companyId`、`storageId`、仓库/物料库区/设备库区 ID、仓库类型及类型内楼层参数、排层列深、访问顺序、阻挡关系、启停与安全门禁、混放配置、容量版本 | 系统→公司→仓库→物料库区→设备库区→储位唯一当前父链，子节点继承根位置；楼层从仓库类型配置读取，深位不可达或门禁失败时硬拒绝，同一 `storageId` 只算一次 |
| 历史逻辑归属 | `logicalScopeId`、物料归属 revision、规则包/执行器版本、空间配置版本及摘要 | 旧物料从持久归属读取，不取最新指针；未归属新物料首次读取时在父任务事务内绑定当前版本 |
| 目标位置配置与实时账 | 有效容量维度/单位/精度、混放键、禁存、稀缺/深位保护、过滤/排序项、占用、有效锁、扣留、设备健康 | `INHERIT/VALUE/CLEAR` 解析并附来源版本；实时账在锁事务中重读。无容量数据时只能按已配置槽位/件数判断，不能把数量冒充体积或重量 |

计划执行请求保存父业务/明细、taskKey、实例、round、动作类型、物料或载具集合、输入摘要、操作者与部门。执行明细保存规则包/空间/日历/单位/容量版本、候选摘要、排序键及原因、锁定前目标建议、最终锁定目标、锁 ID、无解代码及说明。

只读模拟预览使用实时快照，不写计划实例、规则执行记录、锁、释放流水或占用；正式锁计划必须已关联有效父业务。预览只展示可能目标，不构成分配成功。

## 5. 规则版本与载具共同兼容

首次读取的新物料在父任务事务内从权威生效指针获取当前规则包并固化全部依赖版本；已经归属的旧物料从自身归属读取旧版本。同一物料后续任务、任务恢复和并发重算均保持原版本，只有显式归属合并成功后才切换。

含载具时先以载具根及汇合属性做组级预筛，再逐叶子物料校验各自版本规则。预筛不能覆盖、删除或合并掉原单值/集合属性；`ANY` 只按登记语义在该属性集合内成立，安全、禁存、设备限制和容量必须对全部叶子成立。

跨版本建立“叶子物料→规则版本→合法目标集合”的固定映射，只接受能容纳整个不可拆单元的共同交集。任一叶子不兼容即无候选，不任取某一版本，不拆载具，也不因并发重试切换到最新规则。无候选须返回具体叶子、字段、版本、门禁、单位或容量原因。

硬筛选依次检查当前物理树和目标归属、储位/设备启停与安全、模拟后的深位可达、混放与禁存、全部叶子 `ALL` 约束、单位与精度、扣留后容量、占用、有效锁及稀缺保护下限。所有指标按真实 `storageId` 去重；历史逻辑归属只解释来源，不复制容量。

## 6. 候选排序、碎片与批量

硬筛选后按确定键排序：优先已有兼容物料或兼容逻辑归属的储位；随后按稀缺设备/深位通道保护成本和硬保护下限筛选，保护优先于 best-fit，禁止为了填小件而消费唯一大槽位；再对单一可比容量单位按模拟锁后剩余量做 best-fit；多容量维度时按冻结的 `normalizationBasis` 计算残余向量，各维按属性目录顺序比较，不加权成虚假的单值容量；最后以稳定 `storageId` 消歧。

深位候选要模拟本次锁位后的访问路径，不能因填近位导致仍需使用的深位失去可达路径。稀缺设备或唯一通道的保护量计入可分配余量；只有规则明确允许时才消耗，未配置下限不得伪造。排序器只保证同一规则版本和快照下的确定性，不宣称全局最优。

碎片按真实物理储位分别观察：空间碎片看部分占用储位、碎片离散度和最大连续可用份额；兼容性碎片看受限规则签名下仍可容纳的储位数量及最大剩余量；深位阻挡看长期占用后不可达的深位或可达容量损失。它们是独立指标和排序证据，不压成一个未经验证的总分。

批量先按完全相同的容量维度、单位和精度分组，再对不可拆单元按已配置规模做 best-fit-decreasing；不同组不能混排或相加。没有容量数据时只能按槽位/件数规则分组，不能拿件数充当体积。批内影子账只做算法试算，真实原子锁成功后才可置为 LOCKED。

## 7. 计划执行与持久事实

锁位链固定为 `EVALUATE_ALLOCATION(INTERNAL)` → `RESERVE_STORAGE(INTERNAL)` → `VERIFY_ALLOCATION(INTERNAL)`；释放链固定为 `CHECK_RELEASE_EVIDENCE(INTERNAL)` → `RELEASE_ALLOCATION_LOCK(INTERNAL)` → `VERIFY_RELEASE(INTERNAL)`。链内事件使用 `SAME_TX`，每个事件只完成一个领域原子效果，必要流水与投影同事务写入。

| 事件 | 唯一领域效果 | 失败与证据 |
| --- | --- | --- |
| `EVALUATE_ALLOCATION` | 固化父业务挂载、版本、输入、候选和排序解释 | 无候选逐明细解释；只读预览不建实例或锁 |
| `RESERVE_STORAGE` | 按固定储位顺序短锁实时账并原子写入本任务份额或实体槽位 | 竞争失败在原规则版本重选；全成或全不成 |
| `VERIFY_ALLOCATION` | 回读父业务、taskKey、实例、持有人、目标、份额、版本和效果键 | 不一致保持 BLOCKED，不返回锁位成功 |
| `CHECK_RELEASE_EVIDENCE` | 校验失败/取消证据、外部效果和锁持有人 | UNKNOWN/ACCEPTED 不得进入释放 |
| `RELEASE_ALLOCATION_LOCK` | 锁定原锁记录和父任务执行门禁，重验效果证据版本后CAS释放本任务份额，重算聚合可分配量 | SEND_INTENT/ACCEPTED/UNKNOWN/CONSUMED 不得按旧证据释放；不改真实占用，重复调用幂等 |
| `VERIFY_RELEASE` | 确认释放流水、余额和父业务屏障 | 失败保持 BLOCKED，不放行父业务下一步 |

EVALUATE 固化请求、版本、候选、排序和无解解释；RESERVE_STORAGE 在短锁内重读实时安全与账务并原子写锁；VERIFY_ALLOCATION 回读持有人、目标、份额、版本和效果键一致。CHECK_RELEASE_EVIDENCE 校验失败/取消证据和外部效果是否未知；RELEASE_ALLOCATION_LOCK 只释放本任务份额；VERIFY_RELEASE 确认释放事实及聚合重算。释放链不改真实占用。

并发锁失败或容量不足时，保留原 taskKey、规则/归属/单位版本，在原规则版本内重算候选；耗尽则计划结果为 `NO_CANDIDATE`。新候选和原因追加到同一执行记录，不覆盖历史。父业务只按持久实例与屏障推进。

规则执行记录、分配决策、候选摘要、目标建议、锁记录和释放记录分别归属于既有父业务/明细下的一次计划实例；它们不另建业务头，操作者沿用父业务和命令审计。每个不可拆单元对应独立LOCK任务，其资源需求在一次锁位事务中全成或全不成，单任务领域结果为 `LOCKED/NO_CANDIDATE/BLOCKED`；批量父业务按多个任务聚合为 `ALL_LOCKED/PARTIAL/NO_CANDIDATE`，释放批次聚合为 `ALL_RELEASED/PARTIAL/NO_EFFECT/BLOCKED`。这些是业务事实查询结果，不新增或覆盖平台计划状态枚举，父业务不能在PARTIAL时宣称全部分配成功。

计划输入按父业务类型、业务号、明细、round、phase、执行对象集合及有效规则/关系快照摘要计算 `inputHash`；同一 taskKey 相同摘要返回原实例记录，不同摘要拒绝。锁、释放和对账领域记录使用稳定效果幂等键，按平台各自DTO提交，不能把领域效果键强塞进未声明字段的挂载命令。查询、模拟和正式命令使用不同权限与专用 DTO，禁止通用 CRUD 修改锁、占用、版本或历史。

## 8. 入出库挂载合同

| 父动作 | 锁目标 | 实际提交边界 |
| --- | --- | --- |
| 入库 | 目标储位容量份额，或规则要求的实体槽位；不可拆载具整体共同交集 | 可信到位证据后，在本地同事务校验原锁，写库存当前位置和占用份额，锁转 CONSUMED |
| 出库 | 默认锁已明确来源位置的作业资源；只有实际需要内部目标位置时才锁目标容量 | 实际离位事务扣减来源占用并处理本任务锁；不凭锁计划完成就清空来源，也不提前写目标占用 |
| 出库转内部目标 | 来源作业锁和确有需要时的目标容量锁可分别映射 lockKind | 离位与目标到位按真实回执先后提交；每个位置都按自身占用/锁剩余量计算可分配 |

入库到位事务消费原锁并转占用。出库实际离位事务扣减真实占用；来源是否可继续分配，必须按扣减后的剩余占用、其他有效锁、扣留和当前规则重算，不能把来源储位无条件标空。若出库只锁来源作业资源且不发生目标入库，不得伪造目标占用。

上述实际物料提交由父入库/出库业务另阶段任务挂载 `MATERIAL_CHANGE` 计划完成，固定原业务类别、单据及锁记录关联；其 `APPLY_MATERIAL_CHANGE` 在一个 `SAME_TX` 领域动作中提交库存位置/数量、锁消费与占用以及物料溯源历史。分配锁定计划不提前写真实物料变更，释放计划不补写到位事实；父业务也不能先自行提交物料再异步补历史。父业务等待物料变更子任务的持久完成屏障后才进入后续阶段。具体[物料变更与溯源合同](inventory-management-design-20261026.md#111-物料变更计划与溯源历史)以主方案为准。

锁定、释放和物料变更记录均保留 `businessType`（挂载业务类别）与 `planType`，关联父业务号/明细、任务、实例、事件和尝试；审计区分原发起人、实际操作人、执行账号及主体类型、部门、发生/记录时间、原因、来源终端/系统/请求、结果和证据。身份由认证上下文及持久任务解析，系统代执行不能抹除原发起人；失败和未知尝试保留执行审计，不伪造实物变更。

失败或安全取消可挂载 `ALLOCATION_RELEASE`，但设备已接单、回执超时或结果未知时保持 LOCKED 并进入对账；只有证明未入位/未发生外部效果后才可释放。超时只触发提示和对账优先级，不自动释放；UNKNOWN 不换 effectKey 重发，不明结果不得称为取消成功。

释放前检查事件仅产生版本化证据，不能充当之后释放的永久许可。实际释放事务按固定顺序锁定原LOCK记录及父任务执行门禁，重读当前锁状态、发送意图/外部效果、证据revision和任务generation，只在证据仍有效时CAS为RELEASED。设备下发前必须通过同一持久门禁认领并提交发送意图；下发、入库消费与释放互斥，旧generation工作线程不得继续发送。释放先成功则后续下发拒绝；发送意图先提交则释放阻塞，直到对账生成新的确定无效果证据并关闭该发送尝试。CONSUMED只返回已消费事实，不撤销实际占用。此协议不持有数据库事务跨HTTP调用。

后续实际入库或内部移动凭 `parentBusinessId + businessType + lineId + round + taskKey + lockId + storageId + effectKey` 使用原锁，不重复锁同一份额。来源、目标、载具或规则版本不匹配时拒绝并立改派业务。规则版本保持不变，但当前安全门禁、设备健康、深位阻挡和授权在锁定、提交、离位及释放时实时校验。

## 9. 示例

例一：入库单 BO-1 第 2 行的载具 C1 挂载 LOCK 任务 `INBOUND:BO-1:2:C1:1:LOCK`，载具含 V1/V2。V1 允许 S1/S2，V2 只允许 S2，整载具共同交集为 S2；容量不足或 V2 安全约束失败则 NO_CANDIDATE，不拆载具、不改用 V3。取消时另一 RELEASE 任务以相同父业务、allocationUnitId 和 round 标识挂载。

例二：多料储位 S 有 A 占用 30%、B 锁定 20%，剩余 50%。C 的入库任务原子锁 40%；D 随后只看到 10%。C 取消且证明未入位后，RELEASE 计划仅释放 40%，A/B 不变，S 聚合为占用 30%、锁定 20%、可分配 50%。

例三：出库单 SO-1 锁来源 S 中特定库存的离位作业资源，不能因此把 S 标空。实际离位事务扣减其占用后，剩余库存、其他任务锁和规则共同决定 S 的新可分配量；若设备已接单但无法证明离位，锁保持并对账。

例四：S-large 是唯一能容纳合格大载具的候选，保护规则为其登记硬下限。小料 C 虽可 best-fit 进入 S-large，但普通兼容储位仍可用时必须先选普通位；S-large 的受保护空间不能因小件残量更小而先被消费，只有规则显式解除保护时才开放。

## 10. 参数与验收

本期技术参数的推荐初始值以[初始化配置值表](inventory-initial-configuration-20261026.md)为准；下列参数属于可配置边界，已在值表给定的数值无需现场重复猜测。现场设备尺寸、单位、楼层与映射等仍须真实配置；此表不是已经生效的数据库配置。

多维残余归一化基准、保护量和设备访问合同等现场项按值表门禁填写，批大小、分页及嵌套上限等技术值采用表内推荐初值；上线前在隔离环境核验其适用性。参数不得改变父业务身份、不可拆、全叶子安全、物理去重、锁占分离和UNKNOWN不自动释放合同。调整上限不能自动切碎领域原子组或静默截断候选。

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| AR01 | 父业务与计划身份 | 首批入出库及后续已注册业务按允许挂载关系接入，无独立分配业务头；类型选项动态返回，未知/未授权类型拒绝，taskKey包含分配单元不碰撞 |
| AR02 | 锁位/释放实例挂载 | LOCK 映射 ALLOCATION_LOCK，RELEASE 映射 ALLOCATION_RELEASE；一个 phase 任务只有一个实例，重试复用 taskKey |
| AR03 | 无父业务/只读预览 | 正式锁和释放命令被拒绝；预览 query-only，不写锁、占用或正式实例 |
| AR04 | 新物料、旧物料、跨版本载具 | 新物料首次绑定当前版，旧物料用原归属版；逐叶映射共同交集不足即无解，重试不换版 |
| AR05 | 载具单值/冲突集合/ANY/ALL | 原值和叶子引用可追溯，载具汇合先预筛；任一安全/禁存 ALL 失败则整体无候选 |
| AR06 | 输入白名单和单位 | 未登记字段/脚本被拒绝；空值只用 IS_NULL；缺容量只按槽位/件数，数量不冒充体积或重量 |
| AR07 | 兼容储位、稀缺保护、best-fit、多维残余 | 兼容储位优先；深位/稀缺硬下限先过滤，保护成本先于 best-fit；单维或多维排序稳定可重复 |
| AR08 | 批量无解与影子账 | BFD 仅在同维度、同单位、同精度内运行；影子成功不写正式锁，部分无解逐明细返回 |
| AR09 | 多料份额与实体独占短锁 | 多料锁容量份额，独占规则锁实体槽位；数据库锁随短事务释放，不跨搬运持有 |
| AR10 | 并发锁同一储位 | 按储位 ID 排序加锁并重读实时账；竞争者在原规则版重算，不超卖、不覆盖他人份额 |
| AR11 | 入库到位消费锁 | 可信到位证据和库存位置、占用写入同事务；锁转 CONSUMED，失败整事务回滚 |
| AR12 | 出库离位与来源可分配 | 离位事务只扣实际占用；若仍有其他占用/锁，来源只部分可用，绝不无条件标空 |
| AR13 | 失败或安全取消 | 独立 RELEASE 计划只释放本任务份额，不修改物理占用；其他锁/占用保持不变 |
| AR14 | 设备接单、超时、UNKNOWN | 超时不自动释放；保持 LOCKED 并对账；无未入位证明不得释放，不换效果键重发 |
| AR15 | 幂等与结果屏障 | 同 taskKey/inputHash/effectKey 返回原结果，摘要不同拒绝；父业务等待持久屏障，不靠页面状态推进 |
| AR16 | 旧新归属共享物理储位 | 空间、兼容性和阻挡按 storageId 去重，旧新归属不重复占容量 |
| AR17 | 深位与稀缺资源保护 | 不可达位置硬拒绝；保护量计入上限且先于 best-fit；唯一大槽位不被小件先占，无候选说明保护键 |
| AR18 | 主规格计划名一致性 | 只登记 EVALUATE_ALLOCATION/RESERVE_STORAGE/VERIFY_ALLOCATION 与 CHECK_RELEASE_EVIDENCE/RELEASE_ALLOCATION_LOCK/VERIFY_RELEASE |
| AR19 | 检查后并发下发/消费/释放 | 最终释放事务重验门禁、锁及证据版本；下发与释放仅一方取得资格；旧generation不得发送，CONSUMED不被当作可释放份额 |
| AR20 | 物料变更计划与溯源审计 | 入出库挂载物料变更任务后，一次事务完成实存变更、占用/锁消费、溯源；历史写入失败全部回滚，不留下无历史库存变更 |
| AR21 | 挂载类别与执行身份 | 同一计划用于不同父业务时可按businessType定位；发起人、实际操作人、系统执行账号和部门可区分，失败重试审计不重复产生成功物料历史 |
| AR19 | 父业务放行边界 | 锁位 VERIFY 成功才允许真实作业；释放 VERIFY 结束才放行取消收敛，父业务仍等待真实到位/离位证据 |

验收须覆盖事务回滚、锁/占用聚合、至少两个并发竞争者、跨版本载具、不同容量单位、全叶子安全、批量部分无解、预览隔离、出库来源不提前清空和 UNKNOWN 对账。以上是设计门槛，不表示已完成实现、真实库验证、设备联调或全局最优性能证明。
