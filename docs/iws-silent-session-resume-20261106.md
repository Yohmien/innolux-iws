# IWS 刷新静默恢复会话方案

## 问题与目标

浏览器刷新 IWS 页面时，前端只检查 localStorage 中的 IWS Token。Token 缺失后当前实现直接进入 `/login`，该入口又启动认证中心流程，造成：

1. 当前业务 URL 丢失，重新进入时需要再次选择应用入口。
2. 认证、应用授权、票据核销和回跳分成多个可见过渡页。
3. 中心仍有有效登录态时，用户仍被要求重新走一遍认证交互。

目标是刷新后保持当前 URL，在原地显示认证进度，并在中心仍认可当前根会话与 IWS 应用会话时静默签发新的 IWS Token。只有恢复凭据不存在、已失效或中心明确拒绝时，才进入登录入口。

## 方案

### 恢复凭据

IWS 在一次性票据核销成功时，额外写入同源、HttpOnly 的恢复 Cookie。Cookie 值为随机不透明标识，服务端在 Redis 中保存其对应的：

- 当前应用、受信前端、终端。
- 原登录渠道。
- 中心根会话、应用会话标识和代次。

Cookie 不包含可被前端读取的 Token，也不接受前端提交 `userId`、`rootSid` 或 `sessionId`。Cookie 使用 `HttpOnly`、`SameSite=Lax`，HTTPS 请求自动增加 `Secure`。

### 静默恢复

新增目标应用公开接口 `POST /auth/sso/resume`：

1. 从当前 IWS 应用对应的恢复 Cookie 读取随机标识。
2. 从 Redis 读取服务端保存的会话上下文。
3. 调用认证中心 `/iam/session/status`，同时校验根会话、应用会话、代次、前端和终端。
4. 重新校验本地账号状态和当前应用接入权限。
5. 为同一中心会话建立新的 IWS 本地 Token，并刷新当前 Sa-Token 会话中的统一身份上下文。
6. 返回与票据核销一致的会话结果；前端保持原 URL，不经过认证中心页面。

恢复接口只恢复已有关系，不创建认证中心会话，不改变中心应用会话代次，也不绕过中心权限判断。

### 前端守卫

路由守卫在受保护页面检测不到 IWS Token 时：

1. 从最近一次应用会话上下文确定当前应用 API 前缀。
2. 在原页面显示全局认证进度，不清空当前路由。
3. 调用当前应用的恢复接口。
4. 成功后发布新 Token、应用上下文、用户信息和动态路由。
5. 只有恢复明确失败时才转到 `/login?redirect=当前地址`。

恢复开始时建立页面认证门闩。新 Token 已写入但 `getInfo` 尚未完成时，旧页面产生的受保护请求必须等待用户信息验证完成，不能因暂时没有“已验证页面绑定”触发报错和整页重载。

恢复过程使用单页互斥，避免同一页面重复请求；跨标签 Token 写入继续复用现有认证锁与代次校验。

### 登录入口与入口记忆

保留现有认证中心登录页作为无法静默恢复时的兜底。启动登录时优先使用当前请求的应用；未指定应用时使用上次成功进入的同终端应用，避免重复选择入口。

## 范围

- 后端 `iws-admin`：恢复 Cookie、Redis 恢复记录、`/auth/sso/resume`、核销成功写入和退出清理。
- Web：无 Token 守卫恢复、原页面进度遮罩、恢复接口和入口记忆。
- 不新增数据库表，不改变认证中心根会话与应用会话模型。
- 不信任前端传入的身份或中心会话字段。
- PDA 本轮只保持协议兼容，不修改 PDA 页面。

## 验收

1. 已成功登录后刷新任意受保护业务页，URL 保持不变，页面只显示恢复进度并回到原业务页面。
2. 恢复成功后 IWS Token、应用上下文和动态路由均来自同一次中心会话校验。
3. 中心根会话过期、IWS 应用会话被替换、账号停用或接入权限撤销时，恢复失败并进入登录入口。
4. 无恢复 Cookie 时，恢复接口不签发 Token。
5. 退出登录后恢复 Cookie 失效，刷新不能恢复已退出会话。
6. 首次登录或必须重新认证时，登录入口自动沿用上次应用选择。
7. 后端单元测试覆盖有效恢复、无凭据、中心拒绝和上下文不匹配；Web 单元测试覆盖恢复成功、无凭据和守卫回退。
8. 通过后端受影响模块测试与打包、Web `vue-tsc`、定向 Vitest 和生产构建。
