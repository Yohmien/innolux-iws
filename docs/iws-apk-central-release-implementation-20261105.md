# APK 发布管理迁入统一身份认证中心实施方案

版本：V1.0；日期：2026-11-05。

状态：中心、Web、PDA 迁移已实现，并在隔离环境完成真实上传、IMMEDIATE 发布、权限、中心页面、业务 Web 跳转及 H5 登录回调验收。真实中心库的 MCP 只读核验仍未完成，Android 原生更新门禁、真机安装和 C06/C07 组合交付验收保留为未完成项。本次未写真实中心库，未提交、推送或部署。

## 1. 目标与已确认边界

APK 发布管理整体迁入统一身份认证中心，包括管理页面、权限、上传与解析、发布执行、策略调整、版本历史、公开查询、下载、文件引用保护和审计。IWS-A、IWS-B 等业务后端不再独立提供这些能力。

同一 Android 包名共用一个安装包发布序列和更新策略，不按 applicationId、instanceId、公司或所登录业务后端拆分版本。多个历史版本可以保持已发布状态，但最新版本查询必须唯一、确定；不得误改成只能存在一条 PUBLISHED 历史记录。

保留原有账号、角色、公司、部门、岗位、菜单模型和统一管理账号，复用现有页面和能力。验证码关闭、HTTP 可用、Web/PDA 共用并选择业务后端、同类型系统会话互斥、PDA 原生应用图标不变，均为既有基线。

本方案替代此前“统一登录回调后，按最终选择的 IWS 后端检查 APK 版本”的修复方向。正确行为是：所有更新检查与下载始终访问认证中心的统一发布源。

不新增独立 APK 微服务、发布渠道、灰度发布、差分更新、自动停用、自动降级、签名私钥管理或并行账号体系。此前口头列举的功能须以现有代码为准，不将未实现功能伪装成迁移内容。

## 3. 模块与进程归属

### 3.1 迁移方式

优先将现有 APK 包及 Mapper、解析器、发布动作和测试按职责迁入专用业务模块，建议命名 iws-app-release，仅由 iws-auth-server 依赖。这是现有能力的物理抽离，不是重写发布平台或另建进程。

复用已在 iws-auth 的 OSS 服务和现有 iws-process、iws-endpoint 能力。不得为省事让认证中心依赖整个 iws-system、iws-admin 或 iws-wms；也不得让各业务后端通过传递依赖再次加载 APK Controller 或发布执行器。

最终模块名可按实际父 POM 约定调整，职责和启动边界不可改变。仅移除旧模块已经不再使用的依赖，其他业务仍使用的 process、endpoint、OSS 能力保留。

### 3.2 发布执行必须闭合

中心自身承载 APK 发布所需的计划、动作、状态验证、幂等键、目录就绪检查和审计，使用中心所属数据源。保留现有 IMMEDIATE 语义、UNKNOWN 对账和失败重试边界，不能改成 Controller 直接把状态写为 PUBLISHED。

已有代码中的逻辑 systemCode 与 IAM applicationId、instanceId 不是同一概念。盘点现有 IWS 目录标识及环境门禁，给中心建立准确的本地目录归属，不盲目全局重命名，也不能继续依赖 IWS-A/B 的运行表完成发布。

中心可独立启动并提供认证；发布前缺少 process 配置、表或目录时，应明确报告发布不可用，不影响原有登录。正式 APK 发布验收必须证明中心配置就绪并实际执行成功，不能仅以“登录未受影响”完成交付。

不擅自激活现场计划、调用真实上传发布、创建共享环境运行记录或启停现有调度器。需要可写验收时使用确认隔离的测试环境；共享环境的写入和开关变更单列执行项。

## 4. 数据、文件与初始化

认证中心是 APK 发布事实的唯一管理者。优先复用现有 sys_apk_release、OSS 关联和计划事件表模型，先核对真实约束，再决定是否确需结构调整；不预设新增“当前版本表”或复制一套数据模型。

中心初始化必须包含 APK 所需表、菜单权限、文件配置结构和计划事件必要结构。菜单与权限的归属需配套清理业务后端初始化入口，避免新装 IWS 再长出独立 APK 发布源。复用现有 SQL 工程入口，说明执行目标和依赖，不只交零散补丁。

同包名同 versionCode 同摘要重复上传应幂等；同版本不同摘要应拒绝。保持数值版本比较与确定排序，测试并发上传和查询，不能用字符串字典序替代版本代码语义。

文件元数据、对象存储配置、引用检查和删除保护必须与中心发布记录一致。业务后端保留自己的业务附件能力；只共享既有存储技术，不共享彼此 APK 发布事实。不得因迁移误删仍被历史版本引用的文件。

标准化项目不承担旧库兼容，不保留双写、后台复制、旧接口转发或 A/B 更新源降级。已有发布记录、对象文件和待处理计划只做只读盘点并交付处置清单；本次授权不包含写真实库、合并冲突历史、删除源记录或文件。生产切换前必须明确历史保留、重新发布或一次性搬迁的选择及恢复步骤；这不阻止先在新建隔离环境完成实现验收。

## 5. 管理页面、权限与接口

中心 /iam/ 注册并复用现有 APK 页面，在中心菜单提供入口。复用 system:apk:list、upload、publish、download 等现有权限，后端逐接口鉴权，隐藏菜单不能代替访问控制。

上传、列表、历史、策略、发布初始化及重试、页面下载等所有请求，均绑定中心身份和中心 API 基址，不使用当前 IWS 业务 Token。复用中心现有请求适配器及授权机制，不复制页面、不新增平行登录。

移除业务 Web 的本地发布管理路由、菜单映射和相关入口；中心复用的源组件保留。业务后端不得继续响应其 APK 管理、公开查询和下载接口，也不得转发中心接口伪装为独立发布源。

公开版本查询与已发布 APK 下载保留登录前可用范围。上传、策略修改、计划初始化和发布操作必须鉴权。未发布文件不得通过公开接口下载；公开接口不得泄露对象存储凭据或依赖管理端 Token。

优先沿用 /system/apk 与 /app/apk 路径和现有响应结构，只改变所属进程及请求目的地。公开下载代理、对象存储流式输出和下载审计继续复用现有实现。

## 6. 配置与 PDA 更新流程

### 6.1 唯一更新源

优先复用认证中心现有 iam.public-base-url，作为公开 /app/apk 接口的基址；PDA 复用 config.js 中现有认证中心基址配置。路径前缀按实际代理验证，不将页面 /iam/ 路径误当 API 根路径，也不追加业务 /innolux 或 /iws-a-api 前缀。

无需给每个业务后端或每个包名新增更新服务器配置。只有实际存在页面和公开 API 分域部署、且现有基址无法表达时，才增加一个语义明确的中心公开 API 配置，并在文档中解释；不默认扩展多套配置。

更新查询、下载和重试均绑定统一发布源，不经过会把 URL、Token 或响应快照绑定到当前 IWS 的业务拦截器。复用现有 HTTP 技术与超时能力，可为该用途建立小范围中心请求入口；不要重新实现整个 HTTP 框架。

保留各 JAR 所在目录 config 下外部 YAML 优先、包内 YAML 兜底的启动约定，复用已有按应用组织的配置目录；更新认证中心示例及说明，不修改 Job、AI、Monitor 的无关配置。

### 6.2 更新门禁

1. Android 启动或进入登录页时，从中心按真实包名查询版本，沿用现有 forceUpdate、无已发布版本、版本比较和失败关闭策略。
2. 放行后进入统一登录，用户选择任意已接入 IWS。选择仅影响业务连接，不影响更新源。
3. SSO 回调在进入工作页前再次向同一中心复核，覆盖登录期间新发布强制更新的窗口。
4. 复核通过后才完成业务页面导航；需要更新、包信息异常或查询失败时，进入现有更新门禁，不重新开启认证浏览器形成跳转循环。
5. App.vue 前台恢复、版本检查重试、下载、安装返回后复核，始终访问同一中心。
6. 下载继续校验包名、versionCode、大小等既有项目，再调用系统安装器；打开安装器不代表安装成功。原应用签名及原生图标保持不变，不读取或迁移签名私钥。
7. H5 不执行 APK 安装，不因中心 APK 功能影响正常统一登录。

回调异步检查必须保留事务代次和会话所有权校验。旧 A 检查晚于新 B 完成、网络超时、检查失败、退出或重复回调时，旧响应不能导航、清理 B 会话或覆盖新状态。版本检查结果只证明当时策略，不能永久缓存为放行凭据。

更新门禁的页面状态、登录续接与重试应复用现有状态机，明确先检查还是先核销票据的时序及失败后会话清理范围；不得让未检查的业务 Token 触发登录页自动跳入工作台。
