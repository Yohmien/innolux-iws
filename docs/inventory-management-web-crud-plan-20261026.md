## 2. 三类筛选身份与物料变更语义

前端与审计必须分开保存和筛选三类身份，不能用一个状态或编码互换：`businessType` 表示发起并持有业务的事实类别；`planType` 表示拟在统一调度中登记的可复用执行计划；`actualChangeKind` 表示已经落库的领域效果。页面显示名由字典解析，协议值保持稳定。

| 维度 | 建议口径 | 约束 |
| --- | --- | --- |
| `businessType` | 本期交付可扩展业务目录与允许挂载关系，不固定具体作业类型；移库、盘点、入库、出库、拆分、合并等仅作后续接入样例 | 父业务持有单据、明细和提交人；选项来自后端注册目录，不写死前端枚举，物料变更计划不作为业务头 |
| `planType` | 可扩展计划类型目录；MATERIAL_CHANGE、ALLOCATION_LOCK、ALLOCATION_RELEASE仅拟新增示例，当前未注册 | 业务目录返回可挂载类型及版本，前端不写死计划列表；一任务一实例，不代替业务状态 |
| `actualChangeKind` | 位置、数量、生产属性、装载关系、规则归属等领域效果 | 由领域历史在事务内写入；`UNKNOWN` 是外部效果未知，不是效果成功。 |

物料变更是可复用计划能力：本期交付类型目录、允许挂载关系、`MATERIAL_CHANGE` 挂载合同和 fixture；具体父业务类型按后续接入时由目录登记。接入后，父业务按实际作业挂载 `MATERIAL_CHANGE`，任务记录父业务、业务号、明细、taskKey、实例、attempt、效果键和操作人；`ALLOCATION_LOCK` 与 `ALLOCATION_RELEASE` 是另 phase 的分配计划，不能冒充物料变更计划，也不能为 `MATERIAL_CHANGE` 新建独立业务头。平台映射以实际 DTO 为准：`AttachTaskCommand` 已含 `scheduleId/planType/businessType/businessId/taskKey/holdStart/inputHash/rootSet/commandKey`，返回 `instanceId/supervisorInstanceId/mode`；`lineId` 留在父业务与领域任务，`effectKey` 留在计划事件/请求/尝试，不能强塞到挂载命令。现有执行总览按 `businessScheduleCode/businessId/taskKey/planType/instanceId` 筛选；`businessType` 与 `actualChangeKind` 由拟新增溯源查询提供。

领域溯源 DTO 建议使用 `parentBusinessType/parentBusinessId/lineId/taskKey/instanceId/attemptNo/effectKey` 明示来源，保存时把父业务映射到平台 `businessType/businessId`；`lineId` 不进入现有挂载参数，`taskKey` 原样传给平台，实例 ID 取 `AttachResult.instanceId`，效果键取计划事件/请求的实际值。前端只把这些值作为字符串展示和回传，不从名称、状态或 URL 自行拼接。

命令字段必须按各自实际 DTO，不设统一模板：挂载 `AttachTaskCommand` 只使用 `commandKey` 等上述字段，不含 `expectedVersion/reason`；计划动作已有的 `ProcessCommand`、定义命令已有的 `DefinitionCommandRequest` 才按各自声明校验版本与原因。领域聚合命令只有 DTO 定义 revision 时才携带期望版本，只有风险动作合同要求时才强制原因；前端不得向真实 DTO 追加装饰性字段。

生产属性的实体变更由可信父业务挂载 `MATERIAL_CHANGE` 计划任务完成；命令按该任务实际 DTO 校验 revision、原因或证据，通用 `PUT`、Excel 导入和列表行内编辑都不得直接改生产信息、当前库存、父关系或历史。`MATERIAL_CHANGE` 仅指计划，不产生独立业务单。

## 4. 页面与对象呈现

仓库空间页左侧是“系统→公司→仓库→物料库区→设备库区→储位”的唯一树，公司是仓库上位层级。仓库必填 `companyId` 与 `warehouseType`；类型选项包含通用“楼层”，选择后在同一类型配置区维护 `warehouseTypeConfig.floorNo/floorLabel` 及适用外部映射，不将楼层独立到仓库类别之外，不新增楼层树或参考项目专属类型。仓库与物料库区按磁盘管理式容量条带展示总储位、已占用、已锁定、已扣留、不可用、可调整空间。条带选中不可拆下级单元集合，容量按真实 `storageId` 去重；右侧配置、分页储位、库存、规则版本和历史懒加载。范围操作先显示来源/目标、守恒数量、关联移库和阻碍，再提交业务。

公司入口显示基础信息、下属仓库分页和公司范围影响。跨子仓的可见范围、仓库归属、配置调整与退役必须走公司配置/退役业务及计划；纯公司名称/备注修改可在无关系副作用时走单对象审计 CRUD，但通用 CUD 不得接收或覆盖 `warehouseIds`、仓库类型、关系或可见范围。公司只作为对象层和查询权限范围，不新增租户引擎，不重构 Sa-Token、数据源或全局鉴权。

新增仓库、两类库区或储位可先由标准新增入口提交，服务端注册的 `tableCode` 处理器再创建业务草稿并交计划校验/生效；标准编辑可提交已生效配置的变更意图，跨区调整、拆分、合并与退役的实体效果仍按业务/计划落地，发布前不改变生效事实。删除只能退役空范围身份，保留历史和编码；未生效草稿可撤销。拆分集合为空、目标重叠、切碎设备/深位通道、范围非空或任务未收敛时拒绝，并给出可定位的阻碍分页。储位新增、批量生成和导入预览必须按五项地址唯一性（含 NULL 与退役行）预检并分页列出冲突；同一仓库跨设备库区同组合拒绝，精确定位与普通筛选按 §6 区分。

物料页只读汇总按“规则版本+规范化分组值+单位”展示现存量、预留、既有冻结状态（只读）、可用量，展开后服务端分页取物料单元。详情用页签显示公司路径、生产信息、当前物理储位、历史逻辑归属、载具树、锁/占用和追溯；载具树显示单值、多值集合、冲突标记及叶子引用。装拆、换载具走原子关系业务；后续接入 `MOVE` 业务时，根载具移库必须创建 `MOVE` 父业务，取得可信到位证据后由 `MATERIAL_CHANGE` 计划提交位置与 trace，不能把装载关系写入成功当作移库完成。拖动只能生成预览，最终由服务端一次校验环、双父、容量、跨根与目标公司权限。

规则页分开显示定义、草稿、已发布版本和引用摘要；已发布版本的原位事实不可改写，标准编辑可提交变更意图，由服务端生成新草稿或发布业务，发布成功前仍读取原生效版本，也可复制为新草稿。条件/结果只从属性目录组合，预览必须标明规则/空间/单位版本而无副作用。分配锁定/释放、无候选、待处理、对账与已验证结果作为父业务下的执行记录展示，禁止手工新增锁、占用或发布版本。

业务中心保留现有 process 页面作为计划实例的唯一详情入口；在库业务列表增加公司、`businessType`、业务号、状态、发起/执行部门、对象范围和实例链接。公司筛选只缩小服务端已授权的可见范围。状态轮询只针对 `PROCESSING/PENDING/UNKNOWN` 并使用退避，终止或转人工后停止。

物料溯源页以时间线呈现不可变事件，显示事件当时“公司→仓库→物料库区→设备库区→储位”路径的公司编码/名称与仓库类型快照，另设“拆合家谱”“审计表”“版本对比”页签。家谱以有向无环边记录一次拆分的多个目标或一次合并的多个来源，边至少含来源/目标物料、数量、单位、businessType、businessId、lineId、计划/实例/事件引用；它不是当前装载父关系，也不能用并查集替代。对比可选择同对象两个历史版本或两个事件，按字段显示前后值、缺失值、公司/规则版本、证据和状态差异。本期以底座 fixture 验证身份、目录、挂载、快照、幂等和权限，不以移库、盘点等具体作业的完整链作为通过条件。

### 4.1 CRUD 与领域业务判定

判定目标是保住审计和业务不变量，不追求把一切写操作升级成业务单。仅当单个对象、单个原子变化、无跨对象关系、无状态机、无资源锁、无审批、无外部副作用、无分步恢复且可完整记录前后值时，才可保留标准 CRUD，并让对象写入与成功审计在同一事务提交。跨对象关系、状态迁移、容量/装载锁、审批、外部副作用、分步恢复和批导入一律走领域业务与计划；这不授权顺带重构现有全局 CRUD。

页面形态不作为另行审批项。无特殊要求时，列表、查询、分页、列设置、导入模板和导出优先复用 `IwsCrudPage` 及其现有 hooks 与元数据；标准新增、修改、删除、导入仍是统一写入入口，由后端注册的 `tableCode` 处理器依据 DTO 白名单、权限、状态与 revision 选择原子 CRUD+审计或业务/计划。树、容量条带、家谱、流程图等无法由通用表格完整表达时，允许局部扩展必要业务、影响预览或异常处理，或使用专门视图；这些视图仍尽量复用查询、分页、表格、列设置和导出能力。

| 对象或场景 | 结论 | 理由 | 按钮标签 |
| --- | --- | --- | --- |
| 普通字典、纯名称/备注且无引用副作用的草稿调整 | 可保留单对象 CRUD，写入与成功审计同 TX | 单原子、无关系/状态/外部效果；提交前校验 revision 和对象权限 | 新建字典、保存、停用；按对象使用具体动词 |
| 公司 | 纯名称/备注且无子仓影响时可审计 CRUD；配置、可见范围或退役影响子仓时走业务与计划 | 公司是仓库上位且需要跨子仓影响报告；不是租户引擎 | 新建公司、保存名称/备注、提交配置变更、退役 |
| 仓库、物料库区、设备库区、储位 | 领域业务与计划 | 公司/父子唯一、配置版本、范围守恒、容量/占用、阻碍和分步恢复均跨对象 | 创建、提交变更、扩展、收缩、拆分、合并、退役 |
| 物料汇总 | 只读查询，无写能力 | 汇总是规则版本下的查询投影，不是可编辑库存实体 | 查看汇总、展开明细、导出 |
| 物料单元/生产信息 | 已注册父业务挂 `MATERIAL_CHANGE` 计划任务 | 生产属性与库存、归属、锁、审计关联；`MATERIAL_CHANGE` 仅计划 | 变更生产信息；其他领域动词仅在对应后续作业已注册并挂载时显示 |
| 载具主档的独立名称/备注 | 无关系、占用、启停和外部副作用时可 CRUD 并同 TX 审计 | 只有单对象展示字段；一旦涉及生命周期或关系即升级业务 | 保存载具、启用、退役 |
| 载具装载、拆载、换载具 | 领域业务与计划 | 多节点父子、容量、环、根位置和并发关系必须一次原子提交 | 装载、拆载、换载具 |
| 后续 `MOVE` 根载具移库 | 接入时使用 `MOVE` 父业务 + 可信到位 + `MATERIAL_CHANGE` | 关系写入只改变装载父子，不能证明根位置已到位；外部搬运与恢复需独立证据 | 发起移库、确认到位、查看物料变更 |
| 规则定义、草稿、发布、退役 | 领域业务与计划 | 不可变版本、生效 CAS、作用域与运行任务引用涉及跨对象状态 | 保存草稿、复制新草稿、校验并发布、退役 |
| 分配锁/释放执行 | 只能由父业务挂载拟新增计划 | 资源锁、状态机、外部效果与恢复不能由 CRUD 改写 | 查看执行、查证、对账、按允许动作重试 |
| 已注册父业务与物料变更任务 | 业务中心查询，创建经领域命令；任务无独立 CRUD | 父业务持有业务头和屏障，计划实例由 process 推进 | 提交业务、查看实例、取消、处理异常 |
| 物料追溯、家谱、审计 | 只读；仅成功领域事务或系统观测追加 | 历史不可修改，追加审计也不等于库存 delta | 查看证据、对比、跳到当前对象、按权限导出 |
| 批量上传/导入 | 预览后生成领域业务与计划，不直接写生效表 | 批量校验、部分失败、影响范围和重提需要业务边界 | 预览导入、确认生成业务、查看错误 |

保留下来的 CRUD 审计至少含：审计 ID、对象类型/ID、动作、actor/initiator 快照、human 的部门快照、`occurredAt/recordedAt`、前后 revision、变更字段与脱敏前后值、原因、结果、来源模块、请求 ID，以及实际 DTO 声明的 commandKey/幂等键。成功业务变更与其审计、必要历史在同 TX 提交；审计写失败必须整体回滚。

失败命令不生成成功历史、库存 delta 或虚假完成状态；用独立、追加式 attempt 记录保留 commandKey（若 DTO 有）、输入摘要、actor/initiator、对象、告警码、脱敏错误、发生时间与 `FAILED/REJECTED/UNKNOWN`。失败 attempt 可在领域事务回滚后独立提交，但不能顺带提交半成品业务；连失败审计都无法落库时至少保留受控系统日志并明确告警。

历史只读，不提供 edit/delete/import。人工校正必须创建新业务并在新 trace 中记录反向或修正前后值、原因、审批与证据；追加一条审计记录本身不改变库存、容量或状态。审计记录不机械升级为业务头，只有需要状态机、计划或跨对象效果时才建业务。

## 6. 提议契约与一致性

表单初值、字段继承、启用状态、分页/导出上限及首次配置向导统一读取[初始化配置值表](inventory-initial-configuration-20261026.md)对应的后端元数据，前端不另写一组不同默认值。区分“已预置”“未配置”“草稿待发布”和“依赖未满足”；现场必填项缺失时禁用正式执行并给出具体原因。配置向导仅引导补齐和显式发布，不自动创建真实公司、设备或授予角色权限。

以下是拟新增能力清单，不宣称接口已存在。所有 ID 在 JSON 中为字符串；数量、容量、体积、金额及精度为带 scale 的十进制字符串，前端不得转成 `number` 计算或静默舍入。分页统一 `R<PageResult<T>>`，公司/部门范围、筛选项、排序、导出字段和版本均由服务端白名单校验；默认稳定排序至少包含业务时间与唯一 ID，回溯使用页码/唯一键，不允许无界加载。

储位地址写入、判重、通用列表筛选和精确定位共用服务端同一规范化。通用查询中字段未出现表示不过滤，显式空串现在作为该字段的查询条件，不能用来表达 `NULL`；用户用删除键清空文本输入时，前端不发送该筛选参数。通用空串条件按字面空字符串匹配，不匹配 `NULL`；地址列不保存空串，因此该条件不会命中空白地址。精确定位提交五个显式 `{field, value}` 条目，`value:null` 匹配 NULL，空白值按地址规范化归一为 NULL；缺项与 NULL 分开校验，返回 0 或 1 条。精确定位表单中的空字段可提交 `value:null`，不能省略条目或 `value` 键；前端不得按五项文本自行排序或推算深位访问顺序。

元数据只描述展示、查询、表单条件、权限和“可调用哪个领域命令”，不能把任意表名或列名交给通用写入器。拟增 capability 可按命令 DTO 选填 `commandCode`、revision 字段名、幂等字段名、原因策略、`editableWhen`、`disabledReason`；这些不是所有命令的强制字段。缺命令、缺权限或状态不明时 capability 必须为 `false`。上传预览返回规范化行、错误、差异、影响范围、阻塞项、预览 revision 和文件摘要，提交时重新校验并生成业务，不直接写生效表。

接入顺序可为：先注册并验证 `list/meta/export`，再以同一 `tableCode` 注册并验证 `add/update/remove/import` 的受控路由、DTO 白名单、权限、状态、revision 与审计，最后启用对应写入能力。分阶段开放不要求每类对象另建页面或 API。当前组件以 `capabilities?.add !== false` 等方式判断，能力字段缺失时会显示按钮；新元数据必须显式给未接入能力 `false`，不能依赖缺省值。

`IwsCrudPage` 的 `api` prop 已由源码证实存在，可传入 `IwsCrudApi`；类型已包含 `add/update/remove/importData` 等方法，默认 API 也以 `tableCode` 访问同一组入口。现有 `submitForm`、删除和导入在请求返回后一律按成功消息处理并关闭表单或弹窗，尚未区分异步 `accepted`、业务/实例状态与最终生效；拟增一个最小共享结果反馈扩展（当前未实现），至少表达已受理、已完成、业务/实例状态、待处理行、校验错误与 `VERSION_CONFLICT`，失败或冲突时保留用户输入，不能把受理当生效。该组件当前未声明供领域表单或动作复用的 slot 或结果回调，不要将拟增扩展写成现有钩子或 slot；需要复杂影响预览、流程动作或异常处理时可局部扩展或使用专门视图。

与前端同版上线的 SQL 必须同时覆盖空库 init 与既有库 upgrade，并包含菜单、按钮权限、角色授权、`businessType/planType/actualChangeKind/状态` 字典及规则 seed；脚本幂等、编码稳定、重复执行不复制。规则 seed 必须在列表可见并明确显示 `DRAFT/ACTIVE/RETIRED`，不得隐藏或把草稿伪装为已发布；前端从字典渲染状态标识和筛选。

领域审计 DTO 至少保存：对象类型/ID、动作、前后版本或字段差异、公司/仓库路径、物理/逻辑源目标、业务/明细/任务/实例/事件/attempt/实际 DTO 幂等键、规则/空间/单位版本、`occurredAt/recordedAt`、原因、结果和证据引用。`actor` 与 initiator 的快照来自可信父业务认证/命令上下文；executor 只有在真人确认或执行时才保存用户 ID、姓名和部门快照，当前 worker 执行者记为 `SYSTEM/SERVICE` principalCode，不借用或编造用户姓名、部门。历史显示公司、人名、业务名、位置名时均用事件当时快照。

乐观锁冲突使用 `409` 或结构化 `VERSION_CONFLICT`。前端保留用户已填内容，重新读详情、展示本地值与最新值差异，并让用户合并；只把已合并且经服务端确认的字段以新 revision 重提，按该 DTO 更新幂等键。禁止静默覆盖、清空表单、自动反复提交或把冲突当普通网络错误。命令受理只显示“已受理”，以后端实例状态和查询结果作为完成证据。

导出只允许当前用户可见的公司、对象、部门与版本，沿用当前过滤和稳定排序；导出字段必须来自权限过滤后的元数据。默认列设置、查询分页、导入模板和导出复用现有 hooks 与元数据；当前列设置前端保存在 localStorage，后端保存为共享 runtime 配置，尚未实现按用户持久化，文档不得宣称已有用户级保存。用户可在授权范围内调整列显示、查询字段、可编辑字段、规则参数和导出范围；调整只影响个人视图或形成变更意图，列设置开关不改变后端授权，规则参数仍须走白名单、版本、发布与审计，不能借此修改历史或绕过公司/部门范围。`/wms/crud` 是注册后的受控路由，不是绕过领域规则的后门；未注册处理器、历史、锁、分配明细和上传预览不得借通用导入导出跳过权限或审查。二进制下载与 JSON 错误响应分别处理。

## 7. 交互与可访问性

复用现有 Element Plus、表格、反馈与 process 组件，不引入另一套导航或视觉体系。树、条带和表格保持一致的选中上下文；树节点、条带块、行操作均可用 Tab/键盘操作，焦点可见且不被粘性区域遮挡。禁用按钮旁显示具体原因；更稳妥的是保留可聚焦状态并用 `aria-disabled` 解释，避免用户只能猜测为何不能操作。

加载时防重复提交；空列表说明原因并给下一步；请求失败给可重试入口和请求 ID；表单错误滚动/聚焦到首个错误并保留输入。`PROCESSING` 显示进度而非成功，`UNKNOWN` 显示“结果未知，待对账”，仅在后端 `allowedActions` 允许时展示重试/查证；轮询按退避进行，页面隐藏或离开后停止。

历史与执行记录使用明确分页控件和服务端总数；不能在滚动触底时无限拼接。切页保留筛选、排序和选中对象，返回时恢复树展开与滚动位置。对比视图对缺失字段、空字符串、空集合和未知状态分别标记。

PDA 只列扫码必要范围：扫描储位/物料/载具定位、查看关键状态与差异、在已有父业务下提交到位/离位/盘点证据或原因；不做完整 Web 管理页、规则编辑、树形配置或全量导出，也不承诺重做现有 App。

## 9. 验收门槛

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| WC01 | 空间树唯一层级 | 系统→公司→仓库→物料库区→设备库区→储位不跳层，仓库companyId必填；楼层在仓库类型内配置，无独立楼层节点或参考项目专属类别；储位只有一个当前设备库区。 |
| WC02 | 磁盘范围与容量 | 条带按去重 `storageId` 统计；旧新归属共址只计一次；空集合、重叠集合、不可拆单元和双认领均拒绝；同一储位多个根载具/物料按容量、混放和独占规则显示与校验，不新增一储位一容器唯一约束。 |
| WC03 | 拆分/收缩清空门禁 | 有物料、空载具、活动锁、预留、既有冻结状态、开放任务或未决效果时不得提交边界；先完成关联移库并分页列出阻碍；空集合拆分也被拒绝。 |
| WC04 | 公司配置与删除 | 跨子仓的可见范围、归属、配置和退役均产生业务及计划证据；纯公司名称/备注可审计 CRUD；不存在由通用 CUD 改仓库关系或级联删除的入口。 |
| WC05 | 规则版本与旧物料 | 已发布规则的原位事实不可改写或删除；标准编辑只提交生成新草稿/发布业务的变更意图，发布前仍读取原版本；旧物料的新作业仍读取自身持久归属/旧版本，V2 发布不迁移；只有首次归属的新物料或显式归属合并后的物料读取当前生效 CAS。 |
| WC06 | 生产属性变更 | 生产字段实体变更只能由已注册父业务挂载 `MATERIAL_CHANGE` 计划完成；不存在独立 `MATERIAL_CHANGE` 业务头，标准编辑、导入或行内动作即使复用同一入口，也无法直接写实体或绕过任务 DTO 的版本、原因、权限和审计。 |
| WC07 | 锁位、实物变更与刷新 | 选位/写锁是独立短事务，不跨物理作业；实际物料位置/数量变更、消费对应旧锁、占用和 trace 在同一事务提交。命令成功后前端重取物料、储位、容量与锁聚合；初始锁位不能伪装为物理入库完成，未知效果不显示成功。 |
| WC08 | 装载与根载具移库 | 装载/拆载/换载具一次事务处理合法树、根投影和关系历史；根载具移库另走 `MOVE` 父业务，取得可信到位证据后由 `MATERIAL_CHANGE` 提交位置/trace，关系写入成功不能宣告移库完成。 |
| WC09 | 拆分合并家谱 | 一对多、多对一、多对多关系均能追溯来源与目标数量；当前装载父子与生产家谱分开；不能借家谱改当前父级。 |
| WC10 | 新旧规则物料 | 不同规则版本物料共址时各自保留归属和显示版本；物理容量、库存、占用与树不重复计数。 |
| WC11 | 溯源底座 fixture | 仅用隔离 fixture（不是真实业务接入）验证 `businessType/planType` 分离、从动态目录取得允许挂载关系、`MATERIAL_CHANGE` 任务/实例关联、历史中的业务身份/数量/位置/公司路径快照，以及同一幂等键重放不产生二次效果；失败回滚后不留下成功 trace，权限拒绝不落成功记录。不要求移库、盘点、入库、出库、拆分、合并逐业务完成真实链。 |
| WC12 | 目录与三类筛选 | `businessType`、`planType`、`actualChangeKind` 可分别筛选且组合不丢失；允许挂载关系由动态目录返回，不写死前端选项或封闭枚举；前端不把 planType 当业务类型或效果。 |
| WC13 | 历史快照 | 公司路径与仓库类型、真人 actor/initiator/executor 的姓名与部门、业务名、位置名按当时快照展示；worker 只显示 SYSTEM/SERVICE 主体；改名、删身份或权限变化不改写旧记录。 |
| WC14 | 公司与权限导入 | 所有读写、汇总、导出、上传预览、命令和证据均校验公司/对象/部门/状态、字段白名单与版本；用户调整列、查询/可编辑字段、规则参数或导出范围不改变后端授权；隐藏按钮、列设置 `addable/editable/importable/exportable` 开关不能替代后端；任何导入都不能直接写生效表或绕过公司范围。 |
| WC15 | revision 冲突 | 409 保留用户输入，读回最新值并展示差异；合并后重提，不静默覆盖；重复命令键不产生二次效果。 |
| WC16 | 长历史交互 | 时间线、审计和家谱按服务端稳定分页；空/加载/错误/UNKNOWN 可辨认，键盘可完成主要操作，无无限滚动假完成。 |
| WC17 | 执行与业务中心 | 业务列表、计划实例与事件审计能双向定位；现有 process 页面被复用；父业务仅在持久屏障满足后完成。 |
| WC18 | CRUD/业务判定与审计 | 无特殊要求对象复用同一模板；单对象单原子且无关系/状态/锁/审批/外部效果/分步恢复时，注册 `tableCode` 的 `add/update/remove` 原子写入并与成功审计同 TX；其余写操作在同一次请求内路由业务/计划，前端不串联二次动作；历史与批导入不得绕过处理器；失败 attempt 独立留证，不伪造成功变更或库存 delta。 |
| WC19 | SQL、菜单与规则 seed | 同版空库init与既有库upgrade含菜单、权限、字典和规则seed及角色授权候选清单；角色映射经明确配置，不自动批量授予。规则页显示DRAFT/ACTIVE/RETIRED，不以草稿冒充发布。 |
| WC20 | 本期/后续边界 | 本期只交付目录、挂载底座和 fixture，不注册或发布任何具体扩展作业模板；`FREEZE/UNFREEZE` 不进入首期类型、按钮、页面、专属权限、菜单、流程或验收。既有冻结状态仅可只读显示并作为阻碍；后续冻结等类型及模板只文档预留。 |
| WC21 | 同模板双写入链 | 无特殊要求的页面以薄页面复用 `IwsCrudPage`，查询/分页/列设置/导入模板/导出沿用现有 hooks 与元数据；`add/update/remove/import` 经同一注册 `tableCode` 处理器，一次请求分别落到原子 CRUD+审计或业务/计划。前端不自行串联第二条命令；树、容量条带、家谱、流程图等特殊视图可按需求局部扩展或独立呈现，并尽量复用表格、分页与导出。 |
| WC22 | 受理与生效反馈 | 拟增的最小共享结果反馈扩展覆盖已受理、已完成、业务/实例状态、`allowedActions`、待处理行、校验错误与 `VERSION_CONFLICT`；`accepted` 不等于生效，失败或冲突保留用户输入且不清空表单，返回可定位状态和待处理行。列/字段/规则参数调整与导出受对象、公司/部门、字段白名单、版本和权限约束；能力缺失不得默认放行，特殊视图说明需求即可，不新增审批项。 |
| WC23 | 储位地址唯一与输入语义 | 同仓跨设备库区五项组合唯一，NULL 相等、全空每仓至多一条、退役占组合；空串/首尾空格/大小写/全半角/Unicode/前导零按合同判同或判异并明确指出；冲突保留输入并定位到冲突储位 |
| WC24 | 精确定位与深度配置 | 通用查询字段未出现不过滤，显式空串作为条件，清空输入不发送筛选；空串不匹配 NULL；精确定位恰含五条显式字段条目，缺项、缺值键与 NULL 分开，空白值归一为 NULL，`value:null` 匹配空值，返回 0 或 1 条；深度无上限，访问顺序/阻挡/通道成员显式维护；成员变更在旧/新通道存在活动分配锁或 UNKNOWN 时禁用并显示冲突，锁域变化重试不显示为成功 |

以上均为实施与上线门槛。未执行的构建、接口联调、隔离库事务测试、并发测试、设备回执与真实权限验证不得写成已通过。
