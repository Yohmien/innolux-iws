# IWS+ 在库管理完整方案

日期：2026-10-26。状态：已完成源码探索与核心业务访谈，可作为实施输入；本文不是实现或上线验收记录。

## 1. 目标、授权与结论

围绕现有业务、统一调度、计划、事件平台建设在库管理：空间配置决定存放、出入库和展示规则；物料生产属性不因空间调整而被改写。配置生命周期、规则生命周期、逻辑归属变更、实物移动、载具拆装分别以业务事实表达，多步骤通过计划事件推进。

本轮授权包括远端拉取合并、探索、方案及已有项目 Skill 补充；不包括业务代码实施、数据库写入、设备外呼、调度启停、部署或推送。新结构按集中规约直接对齐当前标准，不承担旧版数据兼容；实际实施仍需可重复执行升级和同版应用分批上线设计。

采用四类事实：空间主数据及版本、物料/载具当前关系与占用、持久业务单及任务、不可变历史流水。计划事件平台负责推进，领域服务负责业务不变量，不能用流程状态代替库存事实。

具体初始值、可覆盖范围、发布门禁和现场必填项统一见[初始化配置值表](inventory-initial-configuration-20261026.md)。该表补齐此前未选定的参数，作为本轮推荐初始方案；未部署，也不表示用户逐项确认了其中技术数值。以后调整配置按表内边界与版本化合同办理，不在多份文档维护相互独立的默认值。

本期物料溯源交付聚焦可扩展底座：类型目录、允许挂载关系、物料变更计划及原子提交、溯源/家谱数据合同、审计与通用前端查询。冻结、解冻均不纳入本期实施与验收，也不交付其专属业务单、命令、菜单按钮、权限种子或执行流程。移库、盘点、入出库、物料拆合等作为后续挂载场景描述，不要求为物料溯源验收逐个完成真实业务接入；本期用隔离fixture验证通用合同，不能将fixture通过称为这些业务已接通。此前已确认的空间管理、规则、物料基础管理及分配锁定/释放底座范围保持。

## 4. 空间树与版本化归属

```text
系统（展示节点）
└─公司
  └─仓库（仓库类型、楼层）
    └─物料库区
      └─设备库区
        └─储位

物料/载具 → 当前物理储位ID → 唯一当前空间路径
物料/载具 → 历史逻辑归属ID → 固定规则版本与当时空间版本
```

仓库、库区、储位分别拥有永久内部 ID；编码、名称、外部别名可以变更，不能作为位置外键。库区类型只允许 MATERIAL/DEVICE，并校验父类型和同仓关系。储位是不可再拆的物理地址；排、层、列、深用独立字段描述，深位还需访问顺序和阻挡关系，不能仅多加一个显示数字。

建议模型：`wms_company`、`wms_warehouse`、调整后的 `wms_warehouse_zone`、`wms_storage` 保存稳定身份和当前版本引用；`wms_location_version` 保存不可变配置、父版本及生效记录；`wms_logical_scope` 保存旧/新逻辑归属及所用规则包；`wms_logical_scope_storage` 保存归属对应的物理储位引用。名称是建议，实施时统一字段后落 DDL。

公司是仓库上位管理对象，每个仓库只能有一个当前公司。公司范围与现有对象/部门权限共同校验，不新增租户引擎。楼层属于仓库类型配置：类型选项包含通用“楼层”，其类型参数维护楼层号、名称及适用外部映射（建议 `warehouseTypeConfig.floorNo/floorLabel`）；不设仓库类别之外的楼层类型、独立楼层管理页或额外空间节点。参考项目名不成为业务类型或界面标签。规则通过仓库类型及其楼层参数选择目标仓库，历史保留类型配置快照；跨公司改挂或类型配置变更涉及设备映射和在途影响时走配置业务。公司新增/配置/退役纳入CRUD与业务判定，不能绕过下级仓库引用检查。

当前树的父关系只在当前空间配置中唯一；历史版本引用可以多次指向同一 `storage_id`，但不能生成多个物理占位。跨物料库区真实改挂储位是空间变更业务：检查存量物料的历史归属、开放任务、占用及权限；已有物料保留历史归属，当前物理路径随配置版本展示，禁止静默改写物料归属。

### 4.1 参考磁盘管理的空间分配

借鉴磁盘管理的空间条带、范围预览和操作方式，仓库/库区显示总储位、已占用、已预留、不可用、可调整储位；统计单位为去重的物理储位，重量/体积另按已配置容量展示。条带用于选择与解释集合，不把储位编码连续等同于物理连续。

| 操作 | 范围与结果 | 门禁 |
| --- | --- | --- |
| 创建 | 创建仓库或库区身份，选定允许的完整下级单元建立初始范围 | 不产生双父、不把已有范围复制为新容量 |
| 扩展 | 从同级来源范围选择空闲下级单元，划入目标；上级容器随唯一父关系解析 | 来源需显式授权，待划出单元满足收缩门禁；禁止两个目标同时认领 |
| 收缩 | 从源范围划出指定下级单元，保留源身份 | 先停止该集合新分配，完成移库清空，再释放活动预留、锁和未决任务 |
| 拆分 | 保留源并创建一个或多个目标，划出集合分配给目标 | 与收缩同样先清空；数量守恒、互斥集合及不可拆单元检查 |
| 合并 | 选择保留的目标身份，把源的完整下级单元并入目标，源退役 | 校验类型、配置、权限和任务冲突，固定目标规则；不能丢弃冲突源配置 |
| 删除/退役 | 关闭空范围身份，保留历史 | 无子项、库存、预留、开放任务及未知外部效果 |

仓库合并/拆分处理完整物料库区；物料库区处理完整设备库区；设备库区处理储位集合。需要细分完整下级单元时先办理下级拆分，再办理上级调整，不让单条命令越级复制或切碎关系。跨仓收缩/扩展使用同一重分区业务单原子交接，避免一端释放后另一端尚未接收。

“未分配空间”只表示规划中的未分配容量或尚未被规则选用的储位；已登记储位仍必须保留完整父链。没有落点的范围先创建目标完整链或暂存于明确的规划记录，不能提交父级为空的储位来模拟磁盘未分配区。

空间重分区单 `wms_space_reallocation_order` 及其单元明细建议记录操作类型、源目标ID/版本、拟划出集合、不可拆分组、目标容量、停新分配门禁、关联清空移库单、任务进度、变更前后范围摘要和生效版本。范围调整状态为“草稿→范围锁定→待清空→待提交→已生效”，阻碍或异常显式停留；此为业务状态，不复用平台计划状态。

拆分/收缩执行链：`CAPTURE_SPACE_RANGE(INTERNAL)` 固定集合 → `BLOCK_NEW_ALLOCATION(INTERNAL)` 设置范围门禁 → 业务侧挂载关联移库任务 → `VERIFY_SPACE_EMPTY(INTERNAL)` 核对物料、载具及任务清空 → `APPLY_SPACE_BOUNDARY(INTERNAL)` 在同事务锁内再次复核并提交唯一父关系、配置版本和历史 → `VERIFY_SPACE_BOUNDARY(INTERNAL)` → `RELEASE_SPACE_GATE(INTERNAL)`。

业务任务协调器持久记录移库子任务及完成屏障，通过已发布父计划预留的独立入站合同或本地证据推进；不能在单事件循环调用所有移库动作。目标范围若也是被拆范围，移库必须选择范围外的合法空位，避免把物料搬回即将划出的储位。

“清空”包含物料和空载具的真实占位、活动预留、在途任务、盘点/冻结作业锁以及未决外部效果。不能只核对库存数量为零；关联移库未到位不能解除门禁。真正提交边界前再次锁定集合和版本，阻止预检后被并发写入。

合并完整下级单元可不移动实物；若合并同时重分割设备单元或改变其储位边界，相关部分按收缩/拆分门禁办理。目标配置不兼容时先保持源边界，创建清空或规则例外业务，不强制覆盖。源身份退役不删除旧物料的逻辑归属版本，是否迁入新逻辑归属由独立归属合并单决定。

已提交的空间操作不提供数据库“撤销”按钮；反向调整创建新业务，重新校验当前事实。未提交时取消必须安全收敛移库子任务及未知外部效果，再释放范围门禁；已经搬走的实物保留真实位置，需要恢复则另建反向移库。

## 5. 配置、继承与状态

| 层级 | 可配置内容 |
| --- | --- |
| 公司 | 编码名称、可见部门范围、启用、备注及下属仓库查询；关系和生命周期调整走业务，纯展示字段按CRUD审计判定 |
| 仓库 | 所属公司、编码名称、仓库类型及类型内楼层配置、可见部门集合、启用、入出库策略、存放规则、备注、规则包；分页查看下属储位及分配结果 |
| 物料库区 | 所属仓库、类别、可见部门覆盖、规则包及分配详情、启用、备注 |
| 设备库区 | 所属物料库区、设备类别、固定/可移动、设备系统及下发合同、可见部门覆盖、规则包、启用、备注 |
| 储位 | 唯一设备库区、是否多料、外部系统储位别名、排层列深、启用、备注、可覆盖规则字段 |

固定/可移动描述设备库区的业务特性，设备实时可用性由运行事实记录；移动设备的位置变化不改写储位身份。载具型移动货架与设备库区不是同一实体，应通过设备关联定位。

可继承字段采用 `INHERIT / VALUE / CLEAR` 三态，避免空值同时表示继承和清空。配置查询返回本地值、有效值、来源节点/版本；任务冻结完整有效配置及其摘要。储位的 ID、坐标、父级、设备实测状态不继承。可见部门子级覆盖只能在操作者有管理权限的范围内设置；请求对象范围始终由后端校验，页面隐藏不是授权。

必须分开：配置发布状态 `DRAFT/ACTIVE/RETIRED`、实体生命周期 `ACTIVE/RETIRING/RETIRED`、启用开关、业务单状态、占用状态、设备状态、作业锁。设备状态来自可信设备回报或带权限的人工校正业务，不作为普通配置字段直接编辑。业务单暂用 `DRAFT/SUBMITTED/PROCESSING/BLOCKED/COMPLETED/CANCELLED`，最终枚举须与实现统一；平台实例状态复用现有枚举。

停用阻止新的分配，不抹除现有库存与在途执行；紧急设备禁用属于即时安全门禁，旧规则也不能绕过。继承快照不应使运行任务看不到当前安全停机。

## 6. 物料模型与汇总

“物料主档”和“在库物料单元”分开。物料主档描述品号，在库单元对应一份可追溯标签及数量，不把仓库/库区字段加入生产属性。

| 模型 | 主要字段与约束 |
| --- | --- |
| 汇总规则定义/版本 | 唯一ID、启用、汇总列集合、过滤口径、精度/显示、发布版本；汇总列来自白名单属性目录 |
| 子表规则定义/版本 | 唯一ID、允许单位、层级、生产日期正则及解析合同、周起始日等日历规则、允许批次/供应商/客户/物料属性、数量精度 |
| 在库物料单元 | ID、数量、单位、可空物料层级、原始标签、生产信息ID、存放信息ID、状态、规则版本引用、revision |
| 生产信息 | ID；料号/类别、HF/RS等可扩展属性、生产日期、批次、供应商、客户、尺寸、BOM层级/用量/版本、最终成品料号/类别、外部描述均可空 |
| 存放信息 | ID、物理储位ID、逻辑归属ID、位置状态；仓库/库区由当前路径或历史归属解析，若保留快照必须附来源版本 |
| 关系与家谱 | 当前装载父级和根级见下一节；生产拆分/合并的来源家谱另存，不把装载关系当生产来源 |

用户提出的父级、根级 ID 作为统一节点关系的查询投影提供；不能同时维护两套可独立编辑的父关系。生产信息可空不代表必定满足入库规则：必填要求由对应规则版本明确，缺值匹配用显式 `IS_NULL` 或拒绝，不默认当成通配符。

日期正则只负责格式识别，还需定义提取组、年月日/周码含义、时区、跨年周和无效日期处理；原始标签保持不变，规范化结果附解析版本。BOM 用量和库存数量分开，BOM 路径不等于载具路径。

首页按当前物料单元计算汇总，支持展开分页明细和追溯。聚合键为“规则版本 + 规范化分组值 + 单位”，采用稳定空值编码；默认不跨版本、不跨单位相加。若配置明确换算，冻结换算版本并显示目标单位；载具自身不贡献物料数量，父子遍历必须按物料单元ID去重。现存量、预留量、冻结量、可用量分别展示，可用量按有效预留及扣留集合去重计算，不能简单重复扣减。

数量使用十进制定点数，配置精度不得超过实施时选定的存储精度。第一阶段以现有 6 位为上限，超限拒绝而非静默舍入；需要更高精度时单独调整结构和接口精度合同。此为实施建议，不是新增用户确认。

## 7. 载具与多层装载

以 `wms_load_node` 统一标识 MATERIAL/CARRIER，载具主档记录类型、尺寸、容量、启用等自身属性；`wms_load_relation` 保存当前父子装载关系。每节点至多一个当前父载具或一个直接物理储位；根节点可处于储位、库外、在途或未知位置。子节点继承根的有效物理位置，不能再编辑子节点独立位置。

建立关系时锁定受影响根、节点及目标资源并检查环、自包含、跨根竞争、父级容量、允许类型和状态；根ID/路径为可重建投影，拆载、换父、移根后事务更新。并查集只可作带版本缓存，拆分后失效重建；不能用路径压缩覆盖历史或作为唯一存储。

载具汇总属性只来源于所装物料的有效属性：无冲突呈单值，冲突呈去重集合，空值和不存在分别处理，所有来源可展开。载具自身规格属性与汇总物料属性使用不同命名空间。规则中的 ANY/ALL 对叶子物料求值，标明空集合行为；容量、禁存、安全约束默认要求所有物料均满足，不能用 ANY 绕过。移动载具作为整体移动，但每个物料保留自己的生产信息和规则归属。

装载、拆载、换载具、拆分物料数量、合并物料数量是不同业务。前两者不改变总物料数量；数量拆合需明确标签身份、单位及生产信息兼容规则并追加家谱，禁止把两个不同批次改成一条单值记录。本轮不自行决定不同生产属性的物料可物理合盘。

## 8. 动态设定规则

规则按用途分开：入库可接收、存放归属、候选储位过滤、候选排序、出库可选/顺序、展示汇总。设备下发合同是注册能力引用，不允许在线编写任意 SQL、Java 或脚本。

属性目录提供稳定字段键、类型、来源、允许操作符、集合语义、是否可分组。规则用类型化条件树 `AND/OR/NOT` 加标量/集合操作表达，输出为明确目标、过滤结果或排序项；列名只能从服务端白名单选择。任意新增属性需先登记类型和来源；不能直接拼接列名或让客户端传表达式执行。

规则包括定义、草稿、不可变发布版本、条件项、结果项、作用范围和优先级；规则包版本原子引用各用途版本、空间配置版本、子表/汇总规则版本及日历/单位版本。唯一生效指针使用 revision CAS 切换，发布前校验缺字段、引用、冲突、无候选、同优先级歧义和操作符类型。

| 业务 | 行为 |
| --- | --- |
| 规则配置业务 | 创建/编辑草稿、条件结果及预览，不影响运行任务 |
| 规则设定业务 | 校验并发布不可变规则包，设置作用范围和新读取入口，生成新逻辑归属 |
| 规则执行 | 归属实际入库/出库业务，由其挂载分配锁定/释放计划；保存命中条件、候选、选择及解释，生成分配/预留事实，不另设分配业务单 |
| 规则更新业务 | 基于旧版复制新草稿再发布；不得原位修改已发布内容 |
| 规则删除业务 | 停止新引用并退役，有任务/库存/历史引用的版本保留可读取 |

首次“读取”必须有持久业务语义：尚无归属的新物料或新规则作用域，在任务事务中读取当前规则包并保存版本与输入摘要，和发布事务通过同一生效指针锁或CAS建立明确先后。已经归属的旧物料即便新建作业任务，也从物料归属读取旧规则；不能仅因任务新建便改用最新版。显式归属合并成功后，其后续任务才使用目标归属的规则。一个载具含多版本物料时固定逐物料版本映射，按各自规则共同校验；不能满足整体动作时拆成独立任务或进入待处理，不任取一个版本。

普通页面预览不算占用旧版本；已持久绑定的任务恢复继续原版本。缓存键包含版本及摘要，失效失败也不能让首次分配的新物料取到旧指针；生效指针从权威库读取或经可证明一致的版本校验。任务同时保存所用空间配置、物料归属、规则包及单位日历等依赖版本，避免只冻结规则正文却读到新版参数。

旧版本不删除、旧处理器不静默升级、不回退最新版本；所有被引用版本及执行器须随部署保留。当前安全门禁、真实占用、设备健康在真正分配/执行时重新校验；“旧规则可继续”不保证已失效资源仍可使用。因实际状态变化阻塞时进入业务待处理，只有显式改派业务才换任务快照。

## 9. 新旧逻辑归属与库区合并

例：物料A在储位S，按V1属于旧逻辑区L1。发布V2后物料B读取V2属于L2；L1/L2可共同引用S，S仍只有一个当前设备库区。页面物理树中S出现一次，逻辑归属页分别显示L1/L2及规则版本，物料不会被重复统计。

库区合并业务记录来源归属集合、目标归属、源目标规则版本、候选物料、合并方式、影响摘要和revision。流程为：冻结合并范围 → 按目标规则评估兼容性 → 分批重归属 → 核对收敛 → 退役源归属。合并可跨旧新仓库归属版本，但不隐式修改物理空间树；物理仓库合并另走空间变更/移库组合。

每批固定物料ID、旧归属revision和任务绑定边界，成功项同事务更新逻辑归属及历史；不搬实物、不改生产属性、不增加占用。已被旧任务持久绑定的物料暂缓并显示原因，不能在其执行中偷偷换规则。范围冻结后新到物料不进入本单；续批重试幂等，业务只在全部成功或显式排除已审计后完成。

不符合目标规则的物料保持源归属并列出冲突，不以“合并”强制抹除差异。需要物理调整时创建关联移库单；需要接受规则例外时创建带范围和期限的例外业务。合并启动时先原子停止源归属接收新的首次归属，并把该入口切到已验证目标；已有物料及旧任务继续使用旧版，不因此被阻断。未纳入本单的存量仍可后续另批合并；源归属只有无存量、无运行任务、无未决外部效果才可退役，历史引用仍可查询。

### 9.1 物料分配与锁位

详见[储位分配规则与挂载计划](inventory-allocation-rules-20261026.md)。输入包含物料生产信息、优先载具汇合属性、当前物理空间信息、旧逻辑归属和候选储位实时状态。硬条件先排除不合法储位，再按兼容余量优先、best-fit及批量best-fit-decreasing减少零散剩余空间；尺寸、深位和设备能力不足的候选不参与评分，不把物料数量直接当体积。

分配锁定计划不自动拆载具或物料标签。原子锁位成功后才返回已分配；实际位置仍不变。目标状态为“可分配→已锁定→实际入库成功后占用”，锁定记录持有人入库/出库业务、数量/容量份额、规则版本、任务和revision。允许多料时其他份额可按规则继续分配，不能用单一空闲布尔值覆盖已有占用。

明确入库失败或安全取消后，通过分配释放计划幂等释放本任务锁定并重算可分配余量；设备已受理或外部效果未知时保持锁定并对账，不能只因超时释放。入库成功以可信到位回执和本地库存位置提交为完成合同，同事务消费预留并新增占用，不得先释放后占用留下竞争窗口。出库业务可锁定来源储位作业资源或所需目标储位；解除来源作业锁不等于物料已离位，真实出库后才按剩余库存重算占用。规则预览只模拟，不占资源。

父业务为每个不可拆单元的锁定和释放分别建立任务，例如 `业务ID:明细ID:分配单元ID:轮次:LOCK` 与 `业务ID:明细ID:分配单元ID:轮次:RELEASE`，各挂载一个计划实例并保存关联；不能让同一任务挂两个实例，也不能让同明细多个单元键碰撞。两个计划复用已有统一调度下登记的计划类型，完成屏障由父业务持久协调。决策明细、锁账和释放流水属于父业务的领域事实，不增加独立分配业务头；无父业务不能正式锁位。

## 10. 业务目录及计划事件

业务单保存编号、类型、对象范围、提交人/部门、输入快照、原因、状态及revision；明细记录对象ID、前后版本、预期状态、处理结果。任务保存稳定 `taskKey`、`inputHash`、实例ID、计划定义版本和规则包版本。不同业务类型分别管理校验，不建立任意表名任意字段的通用写入引擎。

物料变更由持久父业务创建任务，父业务保留移库、盘点、入库、出库、拆分、合并等实际 `businessType`，任务使用可复用 `planType=MATERIAL_CHANGE`。一个任务只挂一个实例；`taskKey` 稳定包含父业务/明细/不可拆单元或拆合组 ID/round/phase，重试复用同一键与摘要。业务码、计划类型和模板节点名均为建议命名，尚无注册证据，最终由集中注册清单冻结。

`businessType` 与 `planType` 分别来自可扩展注册目录，本文业务名、编码和计划名均为首批示例，不是封闭枚举。业务类型目录维护稳定编码、名称、状态、契约版本和对象授权策略；计划类型复用现有业务统一调度的允许类型配置，按业务挂载规则选择已发布计划版本，不另建计划引擎。前端类型选项、筛选和允许动作均由后端目录返回，不写死六类业务或固定计划列表。新增类型有已注册能力可表达时经配置校验发布接入，需要新动作时才增加版本化实现；禁止任意类名/脚本执行。已有任务与溯源冻结类型编码、名称和契约版本，停用仅停止新挂载，不能破坏旧实例恢复或历史读取。

| 业务族 | 必备业务 | 计划任务划分与完成事实 |
| --- | --- | --- |
| 空间管理 | 仓库/库区/储位新增、配置变更、删除；仓库/库区合并、拆分、扩展、收缩 | 可独立生效的对象/范围一任务；清空屏障、范围守恒、当前配置指针、版本和历史一致才完成 |
| 规则管理 | 配置、设定/发布、更新、删除；执行复用入库/出库业务 | 发布任务归规则配置业务；分配锁定和释放分别是入库/出库下任务，版本指针、决策和预留可回读 |
| 归属管理 | 库区逻辑合并、例外处置 | 一固定范围批次一任务；归属流水、失败明细和收敛证据 |
| 装载管理 | 装载、拆载、换载具 | 一关系原子变更一任务；合法树、根投影、属性汇合和历史一致 |
| 位置作业（后续接入示例） | 入库、出库、库内移库、跨仓调拨 | 本期定义挂载合同并用fixture核验，不作为溯源底座的逐业务接入验收 |
| 库存控制 | 本期预留/安全释放底座；盘点及差异调整为后续接入，冻结/解冻排除 | 保留库存不变量与业务凭证合同，不将扩展流程列为本期完成条件 |
| 物料变更（底座） | 可扩展父业务创建任务；不设独立变更业务头 | 一可执行事实一任务，父业务类型、原子写入、历史审计和完成屏障通过隔离fixture验收，真实业务后续分别接入 |

删除业务采用退役语义：无子节点、库存、占用、预留、在途任务及未知外部效果才可关闭身份；编码不复用。父节点仍有子项时返回分页阻碍详情，不自动级联删除。未生效草稿可以按明确权限撤销，历史仍留审计。仓库/库区新增可带批量储位生成，但生成规则预览、坐标冲突和结果明细必须可分页核验。

下表为计划模板建议，节点名称不宣称现已注册。每个事件只执行一个领域动作，其必要流水/投影可同事务写入。设备/人工移库及盘点行只说明后续接入边界，不是本期物料溯源底座的真实业务验收项。

| 模板 | 事件链与方向 | 完成证据/异常 |
| --- | --- | --- |
| 空间新增/变更 | `VALIDATE_CHANGE(INTERNAL)` → `APPLY_CONFIGURATION(INTERNAL)` → `VERIFY_CHANGE(INTERNAL)` | 固定影响报告；CAS更新配置和历史；校验器回读生效版本。报告过期则重新评估，不覆盖并发修改 |
| 空间删除 | `CHECK_RETIREMENT(INTERNAL)` → `RETIRE_LOCATION(INTERNAL)` | 第二动作仍在锁内复核新增引用；无库存/开放效果才退役 |
| 空间重分区 | 固定集合 → 阻止新分配 → 移库子任务屏障 → 核对清空 → 原子调整边界 → 核对并解除门禁 | 见§4.1；拆分/收缩不能跳过实物清空，不复用逻辑归属合并冒充空间调整 |
| 规则发布 | `VALIDATE_RULESET(INTERNAL)` → `ACTIVATE_RULESET(INTERNAL)` | 只激活已验证且摘要未变版本；指针与逻辑归属同事务切换 |
| 规则执行/分配 | `EVALUATE_ALLOCATION(INTERNAL)` → `RESERVE_STORAGE(INTERNAL)` → `VERIFY_ALLOCATION(INTERNAL)` | 决策快照；按实际物理储位原子锁定容量并核验持有人，竞争失败可在原规则版本重选，候选耗尽则待处理；入库成功转占用，明确失败/安全取消释放，UNKNOWN保留锁定 |
| 分配释放计划 | `CHECK_RELEASE_EVIDENCE(INTERNAL)` → `RELEASE_ALLOCATION_LOCK(INTERNAL)` → `VERIFY_RELEASE(INTERNAL)` | 由原入库/出库业务另任务挂载；最终释放事务锁定原锁和父任务门禁，重验效果证据版本后CAS，与下发/入库消费互斥；只释放本任务份额，不清除实际占用 |
| 库区合并 | `CAPTURE_MERGE_SCOPE(INTERNAL)` → `CHECK_MERGE_COMPATIBILITY(INTERNAL)` → 每批 `APPLY_LOGICAL_MERGE(INTERNAL)` → `CLOSE_MERGE(INTERNAL)` | 固定批次任务、归属前后值和收敛计数；批次通过业务任务挂载，禁止单事件循环处理无限批次 |
| 载具关系变更 | `CHECK_LOAD_CHANGE(INTERNAL)` → `APPLY_LOAD_CHANGE(INTERNAL)` | 最终动作锁内重新校验并一次写合法关系、投影与流水；无必要不拆出会留下孤儿的中间状态 |
| 物料变更（父业务挂载） | `CHECK_MATERIAL_CHANGE(INTERNAL)` → `APPLY_MATERIAL_CHANGE(INTERNAL, SAME_TX)` → `VERIFY_MATERIAL_CHANGE(INTERNAL)` | 父业务保留实际 `businessType`；库存/位置、装载、拆合家谱、锁消费/占用、历史和 checkpoint 同事务；事实屏障完成后父业务继续 |
| 设备移库 | `RESERVE_TARGET(INTERNAL)` → `SEND_MOVE(OUTBOUND)` → `MOVE_RESULT(INBOUND)` → 挂载 `MATERIAL_CHANGE` 子任务 → 父业务事实屏障 → `RELEASE_RESOURCES(INTERNAL)` | 受理不等于到位；可信回执触发挂载，物料位置、源占用扣减、目标占用及历史在物料变更动作同事务提交；后续只释放设备租约等作业资源，UNKNOWN先查证 |
| 人工移库 | `RESERVE_TARGET(INTERNAL)` → `CONFIRM_PHYSICAL_MOVE(INBOUND)` → 挂载 `MATERIAL_CHANGE` 子任务 → 父业务事实屏障 | 可信扫码/确认回执、来源身份、源目标和物料集合；由父业务等待物料事实，不另设 `COMMIT_POSITION` |
| 盘点（后续接入示例） | 范围快照 → 作业占用 → 录入/复盘 → 差异评估 → 批准调整挂物料变更计划 | 本期仅保留观察与调整分离合同，不实施或验收盘点业务；冻结/解冻流程不在本期模板清单 |

本地事件使用 `INTERNAL + SAME_TX`，业务更新、流水、检查点和事件推进同事务。设备外呼使用注册 `SingleActionOperation`，异步结果独立 `INBOUND`；不得在本地动作内发HTTP。外部效果不明时保留原键并走 QUERY/证据恢复，不换键重发。取消只停新认领并安全收敛，已发生效果使用补偿业务；不能靠回滚数据库宣称实物已回原位。

业务统一调度建议按空间配置、规则、库存作业注册独立业务码及计划类型，资源键统一覆盖物理储位、装载根和设备通道。最终业务码集中定义。默认QUEUE用于多步骤和设备作业；IMMEDIATE仅用于已声明安全失败合同且能在请求内完成的短本地计划，不复制APK样板作为所有流程的默认。

### 10.1 后续扩展边界

冻结、解冻及其他后续业务通过类型注册、能力版本、允许挂载关系、权限合同与独立发布接入。本期不预置可执行冻结/解冻业务，不新增对应按钮或专属种子，不要求其流程验收。现存冻结/扣留状态仍只读保留，并在分配、安全校验和旧库承接中尊重其限制；不为完成底座而清空这些事实。分配锁的安全释放属于已确认底座，不等于解冻业务，继续纳入本期验收。

## 11. 变更历史与审计

配置历史、关系历史、位置/数量流水、物料家谱与变更历史、流程执行审计是五类记录，不能相互替代。建议 `wms_location_change_history`、`wms_load_relation_history`、`wms_logical_assignment_history`，并建立§11.1物料事实历史；扩展库存事实流水关联统一业务号及物理ID。

记录对象ID、动作、前后版本/值、字段差异、物理源目标、逻辑源目标、规则版本、业务单/明细/任务/实例/事件/attempt、幂等键、操作者与部门、来源系统、发生/记录时间、原因、结果。配置生效和历史写入必须同事务；相同幂等键不同摘要拒绝，历史不可编辑删除。对外报文脱敏，保留可核对摘要和受控证据引用。

历史页按对象和时间倒序稳定分页，可从储位查配置、占用、移库、载具和归属变化，按当时名称/编码快照显示并能跳当前对象。物料历史页另支持按业务类别、操作人、时间、物料和多对多家谱过滤。旧版本及被引用处理器保留至最后引用结束且满足审计保留策略；保留年限属于上线前运营配置，不在本轮猜测。

### 11.1 物料变更计划与溯源历史

物料变更使用可复用计划类型 `MATERIAL_CHANGE`，不建立独立业务头。移库、盘点、入库、出库、拆分、合并等持久父业务按实际类别创建任务并挂载；父业务 `businessType` 保留实际注册类型，与 `planType` 分开；派生任务另存 `rootBusinessType/rootBusinessId` 以便追溯来源。业务类别由持久父单和后端校验冻结，名称快照用于审计，前端标签或后续改名不能改变类别。

`taskKey` 至少包含父业务/明细/不可拆单元或拆合组 ID/round/phase，例如 `<父业务ID>:<明细ID>:<单元或拆合组ID>:<round>:<phase>`。父业务持久创建任务，一个任务只挂一个计划实例；重试复用同一键和摘要，不另造业务头。`MATERIAL_CHANGE` 及本节业务码、节点名均为建议命名，尚不宣称已注册。

建议 `wms_material_trace_history` 保存事实头，`wms_material_trace_item` 保存逐物料项；拆分/合并的 N 对 M 家谱以同组多条 item 原子提交。建议字段如下：

| 范围 | 字段与约束 |
| --- | --- |
| 事实与业务 | `traceId`、影响 `materialIds/carrierIds`、`businessType/businessName` 快照、`rootBusinessType/rootBusinessId`、`businessId/businessNo/businessLine`、`taskKey/instanceId/planCode/planType/definitionVersion/eventId/attemptId/effectKey/inputHash`、`reverseTraceId`、`evidenceRef` |
| 物料与生产 | `itemId`、`materialId`、生产信息快照及 revision、数量/单位/前值/增量/后值、物理源/目标 ID 与名称快照、逻辑源/目标、规则包版本、装载父/根前后值、生命周期前后状态 |
| 生产家谱 | N 对 M 边记录 source-target 物料 ID、数量、单位和组序号；不得用当前装载父/根替代生产来源 |
| 审计与结果 | 实际操作人 `actorId/actorName` 快照、发起人 `initiatorId/initiatorName`、部门 ID/名称快照、执行主体 `HUMAN/SYSTEM/SERVICE` 与执行账号、真实发生时的 `onBehalfOf`/授权代办、来源系统/终端/`requestId/sourceTraceId`、发生/记录/提交时间、原因、前值/后值、结果/错误、证据引用 |

生产家谱保存物料来源到目标的多对多关系，不用当前装载父/根替代历史家谱；原始标签和旧物料 ID 保留，数量/单位换算在事实发生时冻结，拆分/合并前后数量守恒，出库进入生命周期终态也不硬删旧 ID。

人工同步操作的身份取当前后端认证，不接受请求任意冒充；异步 `SYSTEM`/worker 取当前系统身份，原发起人和实际操作人取此前可信认证的持久快照，不因当前执行无人工会话而丢失，`SERVICE` 账号不得伪造成自然人。每个流程 attempt 独立写审计，失败、取消、重试、UNKNOWN 不伪造库存 delta；真实物料变更事实与成功 trace 同事务提交，历史写入失败时业务事实和 checkpoint 一并回滚。成功后补偿创建新的反向 trace 并关联原记录，不覆盖旧历史。配置来源、设备来源和外部系统报文只保存脱敏摘要和受控证据引用。

原子链固定为 `CHECK_MATERIAL_CHANGE(INTERNAL)` → `APPLY_MATERIAL_CHANGE(INTERNAL, SAME_TX)` → `VERIFY_MATERIAL_CHANGE(INTERNAL)`。`APPLY` 在同一事务内完成库存/位置、装载关系、拆合家谱、锁消费或实际占用变更、追溯历史和 checkpoint，任一失败全部回滚。跨多物料拆合必须锁整组、单事务 CAS 并使用唯一 `effectKey`；不得把锁消费或转占用与库存/位置及溯源历史拆开。

父业务不得先写库存或位置，再挂 `append-history` 计划补记；一个 `LocalAction` 不得调用其他 `LocalAction` 或嵌套执行计划。存在物理动作的场景由父业务的外部事件完成，可信回执后才挂载本计划子任务并等待事实屏障；生产属性调整、盘点差异批准、纯本地拆分/合并等无外部物理动作的变更直接使用父业务已提交的本地事实，不要求伪造回执。原 `COMMIT_POSITION` 等位置提交模板改为父业务协调等待 `MATERIAL_CHANGE`，避免双写或重复提交。

盘点单纯录入/复盘仅写观察审计，不改实存；只有批准差异调整才挂 `MATERIAL_CHANGE`。若盘点阶段确有移出回库等物理变化，按阶段挂子任务；零差异不得伪造调整流水。载具移动可按载具及叶子物料追溯，但物料数量不得在载具和叶子重复累计。新挂载的物料变更计划沿用物料既定规则归属与冻结版本，不因新任务自动切到最新版；只有显式归属合并等批准业务才改变后续规则。

## 12. 一致性、容量与权限

物理储位是占用权威，逻辑归属只是解释维度。目标储位容量在锁内原子扣占，支持数量/容积/重量及允许混放等已启用限制；未配置的物理容量不假装已验证。多料的“料”以配置的混放键定义，默认建议按物料料号；批次、客户、质量等禁混由规则另约束，不能把“多料”含义硬编码为库存行数。

预留使用独立明细账，包含持有人业务任务、数量/单位、资源、状态、期限和版本，支持同物料多个任务合法部分预留。库存数量预留、储位容量预留、作业锁、设备租约、冻结扣留分别表达；超时不能自行释放未知设备效果相关资源。冻结、出库、盘点、改挂、拆载共享明确冲突检查，锁顺序按物理资源ID固定。

权限复用Sa-Token和对象策略；查询、汇总、分页明细、导出、历史、业务命令和事件回执均校验部门范围。共享物理储位上的旧新逻辑归属权限分别判断，不能通过容量明细泄露不可见物料；容量只返回授权允许的可用性信息。可见部门配置变更必须即时影响查询权限，不因任务旧快照继续泄露；业务执行的规则快照与当前授权校验分开。

## 13. 页面与接口职责

仓储页面遵循项目Skill的[仓储页面复用](../.agents/skills/ruoyi-plus-iws-project/references/project-overlay.md#仓储页面复用)：没有特殊要求默认尽可能复用IwsCrudPage，不作强制限制。用户按权限调整列、字段展示、查询排序、分页、导入模板和导出范围；必要业务/计划由登记的后端写入适配器内置接入，不要求用户离开标准表页或自行串联计划事件。树、条带和家谱等特殊交互可局部扩展或专门呈现，通用能力仍尽量共用。

仓库空间页使用唯一物理树，右侧切换基本配置、分页储位分配、当前库存、规则版本、变更历史；旧逻辑归属在独立视图按规则版本显示，同一储位不复制成第二份物理容量。

前端展示与 CRUD 的完整修订见[Web 页面与 CRUD 完整修订计划](inventory-management-web-crud-plan-20261026.md)。本次纳入设计的是页面、表页/CRUD、API 元数据、权限、乐观并发、真实业务动作与溯源审计页的同交付合同，不是立即业务实施。

配置修改提交变更业务单，显示影响范围和阻碍项。空间管理提供类似磁盘管理的上下布局：上部对象与容量表，下部可选择的范围条带；创建、扩展、收缩、合并、拆分从选中对象发起，提交前显示来源/目标、范围差异、关联移库及阻碍明细。受限操作显示具体原因而非只有灰色按钮。

业务中心统一查看配置变更、规则、空间重分区、逻辑归属合并、装拆、移库、盘点等单据，关联现有计划链/事件详情。规则编辑用属性目录和类型化表单，提供样本预览与冲突解释；发布后只读，可复制新草稿。首页汇总展开分页物料，支持载具树展开，集合属性明确显示多个值。

表页查询和写入优先复用IwsCrudPage、API及元数据能力；写请求在后端按表服务和DTO受控适配，普通原子编辑同事务审计，涉及必要业务语义时由内部创建业务/挂载计划。标准“修改”可以提交生效配置的变更意图，但不能绕过发布或直接覆盖当前事实；历史仍只读。接口沿用项目分页合同和ID精度约定。共享模板补充“已受理/已生效/部分完成/受阻”的准确反馈及实例关联，不将所有提交都提示为修改成功，也不另建第二套计划管理页。

每类CRUD需先评判为“受控CRUD并同事务审计 / 业务命令与挂载计划 / 只读”。无需独立执行和恢复过程的单对象原子编辑可保留CRUD，成功修改与前后值、操作者、部门、时间、原因同事务落审计；失败与重试保留命令审计，不伪造成功变更。状态流转、多对象关系、资源锁、审批、外部调用、多步骤恢复和批量导入转为业务；仓库/库区/储位及物料等已确认必须走业务的边界保持。审计需求不自动产生业务头，也不能成为省略审计的理由；具体对象判定见Web能力矩阵，不顺带重构任务外全局CRUD。

## 16. 验收矩阵

本矩阵对物料溯源只验收底座合同：涉及真实作业的描述使用隔离fixture/模拟证据验证挂载、原子提交和历史，不以真实移库、盘点、入出库或物料拆合接入为本期完成条件。冻结/解冻业务全部排除；本期安全门禁、分配锁释放和现存冻结状态只读保留要求不受影响。

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| A01 | 非法父级、同类嵌套、第二设备库区 | 后端拒绝；储位当前树唯一且同仓关联正确 |
| A02 | 仓库/库区配置继承与覆盖 | 三态解析正确，显示来源版本；任务冻结后不被后续普通配置覆盖 |
| A03 | 有库存/子项/预留/UNKNOWN时删除 | 阻止并提供分页阻碍清单，不级联抹数据 |
