# 业务接入

公共平台和业务能力分开判断。先查当前 Spring 容器、源码和 `GET /process/definition/options`；只有已注册能力无法表达业务事实时才增加实现。验收 fixture 的键、调用和本地写入仅用于说明契约。

## 业务计划边界

IWS 中需要多步骤完成的流程，必须先建立持久业务单或业务任务，再以业务计划接入本平台。普通同步 CRUD，以及同一事务内完成一个领域原子效果（含该效果必需的配套流水或投影），不因此另建多步流程。

业务单和任务身份先持久化，业务调度、计划实例、事件和边共同表达执行。Controller 只接收业务命令，单个 `LocalAction` 只承担一个原子动作，都不能隐式串联后续步骤。

评判现有或拟新增CRUD时，逐对象记录“保留CRUD并同事务审计 / 领域业务与挂载计划 / 只读”的结论及理由。仅有审计需求不强制新增业务单：单对象单原子修改可保留受控CRUD并记录前后值、操作者和原因；涉及状态流转、跨对象关系、资源锁、审批、外部效果或分步恢复时转为业务命令并接入计划。已有明确业务边界（空间变更、物料事实等）不能以“看起来只有一次更新”退回通用CRUD；历史只能追加查询，校正另有可追溯业务。

## 业务身份与冻结事实

| 事实 | 合同要求 |
| --- | --- |
| 业务单 identity | `businessType` 界定业务域，`businessId` 指向持久业务单；业务单身份创建后不复用。 |
| `taskKey` | 标识业务单下可独立挂载、执行和恢复的任务；`businessType:taskKey` 是平台幂等键。同一任务重新办理时使用新 `taskKey`，旧记录保留。 |
| `inputHash` | 对本次任务的有效输入做规范化摘要。同 `taskKey` 同摘要返回原实例，不同摘要拒绝覆盖。 |
| 计划版本 | 实例冻结 `planCode`、`versionId` 和 `revision`；运行中发布新版本只影响后续实例。 |
| 业务规则快照 | 冻结本次任务使用的规则、参数、范围和来源摘要，并保留可回读引用；后续配置变化不回写既有实例。库存已有归属时，新建任务仍按原归属版本取规则，只有显式归属变更成功才切换；首次归属的新物料才读取当前生效包。 |
| 任务实例映射 | 业务任务持久保存 `taskKey`、`planInstanceId`、状态、计划版本和规则快照；业务单可定位任务与实例，实例可回读业务单和任务。 |
| 挂载业务类别与审计 | 固定父业务 `businessType`、业务单/明细及当时名称，不以 `planType` 代替业务类别。审计分别记录发起人、实际操作人、执行账号及主体类型、部门、时间、原因、来源请求与结果；身份来自服务端认证和持久父业务，不接收客户端冒充身份。 |

一个业务单可以产生多个业务任务，每个任务映射一个业务计划实例。不要用同一 `taskKey` 并发创建两个实例；任务重开、补偿或再次办理时建立新的任务身份。

`businessType`（业务类别）与 `planType`（计划类型）是两个可扩展目录，后文编码只作首批示例，不能写死为前后端封闭枚举。复用现有业务统一调度配置可挂载计划类型及版本化能力；新增类型需注册、权限/合同校验和发布。选项由后端返回，运行记录冻结编码、名称及契约版本；类型停用不删旧实例能力或历史。类型目录不能演变为执行任意类名或脚本的入口。

## 规划与执行分离

建计划阶段只定义业务身份字段、状态、事件、边、动作合同、完成证据和版本。草稿、校验和发布都不得激活业务执行，也不得创建外部副作用、预写业务完成状态或提前调用本地动作。执行从持久业务事实、已发布实例和明确命令开始；外部触发仍先在业务适配层定位或挂载实例。

## 方向与拆分

| 需求 | 方向 | 事件内容 | 后续 |
| --- | --- | --- | --- |
| 外部系统通知 IWS，或业务节点已到达 | `INBOUND` | 一个调用合同，通常是 `TRIGGER_EVENT` | 推进匹配事件，执行仍按方向动作 |
| IWS 调外部系统 | `OUTBOUND` | 一个调用合同、系统、端点、效果键 | 异步受理后另立结果 `INBOUND` |
| 只在 IWS 本库改状态或计算 | `INTERNAL` | 一个 `SAME_TX` 本地动作和本地效果键 | 写入、检查点和后继激活同事务 |

每个事件只有一个方向和一个动作。一个业务步骤需要多个可观察的领域效果时，按效果拆事件和边；不能在入站或出站操作内部调用第二个动作、发送额外 HTTP 或回写事件来隐藏后续步骤。同一事务内完成一个领域原子效果并写入其必需的配套流水，仍作为一个 `INTERNAL` 动作，SQL 条数不是拆分标准。多个入站前驱汇合使用独立事件、`AND` 边或同一 `joinCode`。

## 扩展接口

| 接口 | 用途 | 接入核对 |
| --- | --- | --- |
| `EventTypeProvider` | 登记事件类型和支持方向 | `key@version` 唯一、方向准确 |
| `SingleActionOperation` | 执行一个入站或出站逻辑调用 | 合同键/版本、方向、用途、完成合同、资源键 |
| `LocalAction` | 执行一个 `SAME_TX` 本地动作 | 动作键/版本、checkpoint、本地效果键 |
| `StateValidator` | 发布或跳转前校验结构/本库证据 | 精确版本和失败原因 |
| `BranchCondition` | XOR 边的只读条件 | 条件版本、边优先级 |
| `InboundIdentityPolicy` | 把服务端认证上下文绑定到可信来源 | 从请求字段自报身份不可作为授权 |
| `ProcessAccessPolicy` | 实例、事件、调度的对象范围 | 默认拒绝；普通角色不授予全范围 |
| `ImmediateFailureContractProvider` | 声明即时动作的安全失败合同 | 每个可达动作有合同 |
| `ImmediateInputEvidenceProvider` | 返回已持久、未绑定的即时回执 | 按事件和唯一回执读取，不按参数编造 |

能力键和版本直接注册到 `CapabilityRegistry`，重复键启动失败，运行时不回退最新版本。

2026-10-23 源码核验时，只在测试 fixture 中找到业务方向、合同、本地动作和身份策略；process 内部的监督 `LocalAction` 不属于业务扩展。

2026-10-26 的 APK 发布已成为主源码业务样板：事件类型为 `INTERNAL`，监督模式为 `IMMEDIATE`，发布动作为 `SAME_TX`，并注册状态校验、对象范围和即时失败合同，见[计划定义与事件编排](../../../../iws-modules/iws-system/src/main/java/com/innolux/iws/system/apk/process/ApkPublicationProcess.java)、[发布本地动作](../../../../iws-modules/iws-system/src/main/java/com/innolux/iws/system/apk/process/ApkReleasePublicationAction.java)和[真实定义发布验收](../../../../iws-modules/iws-system/src/test/java/com/innolux/iws/system/apk/process/ApkPublicationProcessMysqlIntegrationTest.java)。该样板证明本系统内部同步发布动作已接线，不证明生产 `OUTBOUND`/HTTP 外呼、外部结果回调或真实生产执行已经发生。生产接入仍以当前源码、能力查询与发布校验证明 Bean 已注册。

## 三类动作

- `INBOUND`：合同声明精确 `key/version`、`OperationKind`、`CallPurpose`、`CompletionContract` 和 `callerCandidates`。结果回调使用另一个 `INBOUND + RESULT_CALLBACK`，其 `originOutboundEventId` 指向同实例的原出站事件。
- `OUTBOUND`：合同给出一致的方向、用途、完成合同和非空 `resourceKey`；`ACCEPTANCE` 只表示外部受理，必须安排结果事件。执行实现只完成这一份逻辑调用，返回证据或 `UNKNOWN`，不回写事件、token 或 attempt。
- `INTERNAL`：合同、HTTP 效果键、端点、用途和完成合同为空；动作只写本库一次，不调用 HTTP、第二个动作或生成调用许可。该次写入可包含同一领域原子效果必需的流水和投影。

## 业务终态与流程终态

业务单和任务的终态来自业务表及其配套领域事实；计划实例、事件和完成证据给出流程终态。两者分别命名、分别更新。

`COMPLETED` 只表示实例按完成合同收口，不能用来断言配置已生效、库区已合并或载具已拆装。业务关闭必须以业务后置校验达标为前提：确认全部必需业务步骤已执行、业务事实已落库且满足验收条件；不能设计流程成功而必需业务步骤没有事件、动作或证据的计划。计划进入 `CANCELLED`、`FAILED_FINAL` 也不能反推业务已完成回滚，业务单可能仍处于待生效、待搬运或待补偿。

## UNKNOWN 与重试

- `SAME_TX` 本地动作失败时，一次领域写入及其流水回滚。恢复按当前事件、业务事实和平台校验执行，不能把失败事务拆成多个动作或手工补一条成功记录。
- `OUTBOUND` 发送意图已持久化、响应超时或结果不明时进入 `UNKNOWN`。先读取原请求、效果键、尝试和检查点，再走结果 `INBOUND`、显式 QUERY 对账或恢复；普通重试不能盲目重发未知外部副作用。
- 重试保持同一业务单、任务、`inputHash`、计划版本和业务规则快照，只恢复尚未收口的执行事实；普通执行尝试仍属于原任务。只有重新办理或独立补偿才建立新任务身份并记录关联，旧事件和尝试保留。

## 补偿、取消与历史

- 取消计划只停止新认领并等待安全收敛，不能取消已经发生或仍未知的外部副作用。业务取消是独立业务命令；需要撤销物理或领域效果时，建立补偿业务单、任务和计划实例，每个补偿事件仍只承担一个方向和一个动作。
- 历史按追加方式保留业务任务到实例的映射、事件、尝试、请求、检查点、证据、审计、计划版本和业务规则快照。已成功、失败或未知的旧事实都保留可追溯关联，不用删除、覆盖或用旧 `taskKey` 重建实例来清理历史。

## 业务建模样例

库存领域的具体结构和不变量由 `docs/inventory-management-design-20261026.md` 维护；下列只说明计划事件接入边界。

| 场景 | 业务单与任务 | 事件边界 |
| --- | --- | --- |
| 仓库配置变更 | 变更单冻结唯一当前树 系统 → 公司 → 仓库 → 物料库区 → 设备库区 → 储位的范围、变更项和生效条件；楼层包含在仓库类型配置内，储位只归属于所在设备库区。 | 校验、应用和生效按可观察效果拆事件；单个应用事件只落一个配置原子效果及配套流水。业务单未生效时，计划完成不能写成配置已生效。 |
| 库区逻辑合并 | 合并单记录源/目标库区、范围和生效时间；默认执行业务逻辑合并，需要物理搬运时另立移库单。 | 新旧规则并存，旧物料保留旧逻辑归属。旧逻辑归属通过历史版本引用共享物理位置，唯一当前树中的物理储位仍只有一个设备库区父级，不因合并新增第二个当前父级；容量只按物理事实计一次。合并任务的事件分别处理范围冻结、逻辑归属、历史引用和旧归属关闭。 |
| 空间合并、拆分和范围调整 | 仓库/库区按磁盘管理式范围操作建立重分区单；边界按集合及不可拆单元，不要求编码连续。 | 物理空间边界调整与逻辑归属合并分开。拆分/收缩先阻止范围内新分配，移库清空后在锁内复核并提交边界；移库子任务、清空屏障和门禁释放均有持久完成证据，取消不假定已搬实物自动回原位。 |
| 载具拆装 | 拆装单按父载具建立任务，冻结组件集合、属性和目标关系。 | 校验/冻结与应用可分事件；同一关系变更所需解绑、绑定、根投影、属性汇合及历史在一个 `SAME_TX` 动作内原子完成，不制造孤儿中间状态。无冲突属性呈单值，冲突属性保留集合并显式采用 `ANY`/`ALL`。并查集只能作辅助，不能替代持久关系。 |
| 分配锁定与释放计划 | 由入库/出库业务分别创建阶段任务挂载锁定计划、释放计划，冻结不可拆单元和规则版本；不设独立分配业务单。 | 入库成功同事务转占用；失败或安全取消另任务挂载释放计划。最终释放事务重验锁、父任务门禁和效果证据版本，与下发/消费互斥；只释放本任务份额，不抹除真实占用。UNKNOWN保持锁定对账。详见[分配规则与挂载计划](../../../../docs/inventory-allocation-rules-20261026.md)。 |
| 物料变更计划 | 移库、盘点、出库、入库、拆分、合并业务为物料变更分别建立任务，挂载 `MATERIAL_CHANGE`；不另建物料变更业务头。 | 校验→原子应用→核验。一个 `SAME_TX` 动作内完成本次物料事实、必要占用/锁消费、拆合家谱和溯源历史；父业务不得先改库存再挂计划补记历史，也不得在动作内嵌套执行另一计划。溯源记录父业务类别、单据、计划及人员审计；失败/取消/UNKNOWN写执行审计而不伪造成功物料变更，盘点观察不等于库存调整。细节见[主规格物料变更与溯源](../../../../docs/inventory-management-design-20261026.md#111-物料变更计划与溯源历史)。 |
| 后续扩展接入 | 冻结、解冻及其他扩展业务后续独立注册、配置和发布，本期不交付其专属流程、按钮或执行种子。 | 本期以隔离fixture验收目录、挂载、原子事实、审计和历史合同；不要求逐个真实业务接入，不将fixture写成生产接线证据。既有冻结事实仍只读尊重，分配锁安全释放继续验收，不等同解冻业务。 |

## 首次外部接单

外部触发不负责创建计划实例：`POST /process/instance/{instanceId}/trigger` 只按现有实例和入站合同匹配事件，不自动挂载、物化或定位业务实例。业务适配层在首次外部接单时必须先明确任务挂载或已存在实例的定位，再把有效 `instanceId` 交给触发入口；无法确定实例时由业务侧先完成挂载或按既有业务事实查找，不能依赖 trigger 隐式建实例。

## 接入验收

先确认能力出现在 `GET /process/definition/options` 和草稿的 `edit-capabilities`，再校验并发布。重点测试重复键、错误版本、可信来源缺失、重复来源键、载荷不一致、任务实例映射、业务/流程终态分离、结果事件关联、取消与补偿、事务回滚和 `UNKNOWN`。fixture 通过不能证明生产 Bean 已接线。
